## 虚拟内存

* 单片机的CPU直接操作内存的**物理地址**。在这种情况下，要想在内存中同时运行两个程序是不可能的，因为如果第一个程序在某一位置写入一个新的值，将会擦掉第二个程序存放在同一位置上的所有内容。
* 操作系统通过进程将程序的运行环境隔离开来，给不同的进程分配独立的内存空间，即一套虚拟地址空间。操作系统提供一种机制，将不同进程的虚拟地址和不同内存的物理地址进行映射，使得每个进程都以为自己独占了全部的内存，从而可以允许多个程序同时运行。**每个程序只关心自己的虚拟地址就可以，实际上大家的虚拟地址都是一样的，但分布到物理地址内存是不一样的。作为程序，也不用关心物理地址的事情。**

***虚拟内存地址**和**物理内存地址**：程序中使用的内存——虚拟内存地址，在物理内存中实际存放的位置——物理内存地址。

* 进程持有的虚拟地址会通过CPU中的内存管理单元 `MMU`的映射关系，来转换成物理地址，然后再通过物理地址访问内存。

### Linux中的虚拟内存

Linux 系统中虚拟空间分布可以分为 `用户态`和 `内核态`两个部分。虽然每个进程都各自有独立的虚拟内存，但是**每个虚拟内存中的内核地址其实关联的都是相同的物理内存**，这样进程切换到内核态后，就可以直接访问内核的代码和数据。

* 用户态段分布：

  1. 代码段
  2. 数据段
  3. BSS段
  4. 堆
  5. 文件映射
  6. 栈

完整的程序内存布局通常包括以下几个主要部分：

### 1. **代码段（Text Segment）**
- **用途**：存储程序的可执行指令，即编译后的机器代码。
- **特点**：
  - **只读**：防止程序意外修改指令。
  - **共享**：多个进程可以共享同一个代码段，节省内存。
  - **不可修改**：程序运行时，代码段的内容通常不允许修改。

### 2. **数据段（Data Segment）**
- **用途**：存储已初始化的全局变量和静态变量。
- **特点**：
  - **可读写**：程序可以读取和修改数据段中的内容。
  - **初始化**：在程序启动时，数据段的内容会被初始化为程序中定义的值。

### 3. **BSS段（BSS Segment）**
- **用途**：存储未初始化的全局变量和静态变量。
- **特点**：
  - **自动初始化为零**：程序启动时，BSS段的内容会被自动初始化为零。
  - **不占用可执行文件空间**：BSS段的内容在可执行文件中不占用空间，仅在程序运行时分配内存。

### 4. **堆（Heap）**
- **用途**：用于程序运行时的动态内存分配。
- **特点**：
  - **动态分配**：通过 `malloc`、`calloc`、`realloc` 等函数动态分配内存。
  - **手动管理**：需要程序员手动释放内存，防止内存泄漏。
  - **向上增长**：堆的内存空间通常从低地址向高地址增长。

### 5. **栈（Stack）**
- **用途**：存储局部变量、函数调用信息（如函数参数、返回地址等）。
- **特点**：
  - **自动分配和释放**：由系统自动管理，函数调用时分配内存，函数返回时释放内存。
  - **向下增长**：栈的内存空间通常从高地址向低地址增长。
  - **局部作用域**：栈中的变量仅在函数调用期间有效。

### 6. **内存映射段（Memory Mapped Segment）**
- **用途**：用于高效的I/O操作和共享内存。
- **特点**：
  - **共享内存**：可以用于进程间通信，多个进程可以共享同一块内存区域。
  - **映射文件**：可以将文件映射到内存中，提高文件读写效率。

### 7. **常量区（Constant Segment）**
- **用途**：存储程序中的常量数据，如字符串常量、数字常量等。
- **特点**：
  - **只读**：常量区的内容在程序运行时不允许修改。
  - **共享**：常量区的内容通常可以被多个进程共享。

### 内存布局示意图
从低地址到高地址，程序内存布局通常如下：
1. **代码段（Text Segment）**
2. **数据段（Data Segment）**
3. **BSS段（BSS Segment）**
4. **堆（Heap）**
5. **内存映射段（Memory Mapped Segment）**
6. **栈（Stack）**
7. **内核空间（Kernel Space）**

程序内存布局的描述存在差异，主要是因为不同的场景和视角下，内存布局的划分方式和关注点有所不同。以下是对“常量区”和“内核空间”在程序内存布局中的不同描述的解释：

### 1. **常量区**
常量区是程序内存布局中的一部分，用于存放程序运行期间不可修改的数据，例如：
- **字符串常量**：如 `"Hello, World!"`。
- **数字常量**：如定义的 `const int MAX = 100;`。
- **其他只读数据**：如数组常量等。

常量区的特点是：
- **只读性**：存储在常量区的数据在程序运行期间不能被修改。
- **共享性**：常量区的内容通常可以被多个进程共享，因为它们是只读的。
- **位置**：常量区通常位于代码区附近，因为它们的内容在程序编译时就已经确定。

### 2. **内核空间**
内核空间是计算机内存中的一部分，专门用于操作系统内核的运行。它与用户空间（程序运行的空间）是分开的。内核空间的主要作用是：
- **保护操作系统的核心功能**：内核空间包含操作系统的核心代码和数据结构，这些内容对用户程序是不可见的，以防止用户程序对系统造成破坏。
- **提供系统调用接口**：用户程序可以通过系统调用（如文件操作、进程管理等）与内核空间交互，但不能直接访问内核空间的内存。

### 3. **为什么会有不同的描述**
- **不同的视角**：
  - **从程序设计的角度**：常量区是程序内存布局的一部分，关注的是程序内部的内存分配和使用。例如，在C/C++程序中，常量区用于存放字符串常量和全局常量等。
  - **从操作系统和硬件的角度**：内核空间是整个计算机内存布局的一部分，关注的是操作系统如何管理内存，以及如何保护系统资源。

- **不同的应用场景**：
  - **常量区**：主要用于描述程序运行时的内存布局，特别是程序内部的静态数据存储。
  - **内核空间**：主要用于描述整个计算机系统的内存布局，特别是操作系统如何管理内存资源。

### 4. **总结**
- **常量区**是程序内存布局的一部分，用于存放程序运行期间不可修改的数据。
- **内核空间**是计算机内存布局的一部分，用于存放操作系统的核心代码和数据，以保护系统资源并提供系统调用接口。

这两种描述并不矛盾，只是关注的层面和应用场景不同。

### 总结
这些内存区域的划分有助于合理管理程序的内存资源，确保程序的高效运行和安全性。不同区域的内存具有不同的读写权限和管理方式，程序员需要根据程序的需求合理使用这些内存区域。

  **其中，堆和文件映射段的内存是动态分配的**。比如，使用C标准库的 `malloc()`或者 `mmap()`，就可以分别在堆和文件映射段动态分配内存。

## `malloc`和 `free`是操作内存

* malloc()并不是系统调用，而是C库的函数。malloc()申请内存的时候，会有两种方式向操作系统申请堆内存。

  1. 通过 `brk()`系统调用从堆分配内存
  2. 通过 `mmap()`系统调用从文件映射分配内存

  malloc()源码定义了一个阈值，当用户申请的内存小于这个阈值时，通过brk()申请内存；当用户申请的内存大于这个阈值时，通过mmap()申请内存。（128KB，不同的glibc版本定义的阈值也是不同的。）
* malloc()申请的是虚拟内存，**如果分配后的虚拟内存没有被访问的话，虚拟内存是不会映射到物理内存的**，这样就不会占用物理内存。只有在访问已分配的虚拟地址空间的时候，操作系统通过查找页表，发现虚拟地址没有映射到物理内存，就会产生缺页中断，然后操作系统会分配物理内存，建立虚拟地址和物理地址的映射关系。
