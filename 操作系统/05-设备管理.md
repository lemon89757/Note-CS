# 设备管理

## I/O设备的概念和分类
![](../img/05-设备管理/250216-150835.png)
- 块设备：传出快，可寻址（可以随机地读写任一块）
- 字符设备：传输慢，不可寻址，**常采用中断驱动**方式

1. 概念：
   * “I/O” 即“输入/输出”。I/O 设备就是可以将数据输入到计算机，或者可以接收计算机输出数据的**外部设备**，属于计算机中的硬件部件。
   * 在 `UNIX` 系统中将外部设备抽象为一种特殊的文件，用户可以使用与文件操作相同的方式对外部设备进行操作。
2. 分类
   * 按使用特性：人机交互类外部设备（数据传输速度慢，如鼠标、键盘）；存储设备（数据传输速度快，如移动硬盘）；网络通信设备（数据传输速度介于上述二者之间，如调制解调器）
   * 按传输速度分类：...
   * 按信息交换的单位分类：块设备（数据传输的基本单位是“块”，数据传输的基本单位是字符）

## I/O 控制器
![](../img/05-设备管理/250217-204423.png)
I/O 设备**由机械部件和电子部件（I/O 控制器/设备控制器）组成**，用于实现对 I/O 设备的控制。
- 机械部件：主要用来执行具体 I/O 操作；
- 电子部件：通常是一块插入*主板*扩充槽的印刷电路板；`CPU` 无法直接控制 I/O 设备的机械部件，因此 I/O 设备还有一个电子部件作为 `CPU` 和 I/O 设备机械部件之间的“中介”，用于实现 `CPU` 对设备的控制。

### I/O 控制器的功能
![](../img/05-设备管理/250217-201607.png)
1. 接收和识别 `CPU` 发出的命令
    如 `CPU` 发来的 `read/write` 命令，I/O 控制器中会有相应的**控制寄存器**来存放命令和参数。
2. 向 `CPU` 报告设备的状态
    I/O 控制器中会有相应的**状态寄存器**，用于记录 I/O 设备的当前状态，如 1 表示空闲，0 表示忙碌。
3. 数据交换
    I/O 控制器中会设置相应的**数据寄存器**。输出时，数据寄存器用于暂存 `CPU` 发来的数据，之后再由控制器传送设备；输入时，数据寄存器用于暂存设备发来的数据，之后 `CPU` 从数据寄存器中取走数据。
4. 地址识别
    类似于内存的地址，为了区分设备控制器中的各个寄存器，也需要给各个寄存器设置一个特定的“地址”。I/O 控制器通过 `CPU` 提供的“地址”来判断要读写的是哪个寄存器。

### I/O 控制器组成
![](../img/05-设备管理/250217-202606.png)
1. `CPU` 与控制器的接口
    用于实现 `CPU` 与控制器之间的通信。`CPU` 通过控制线发出命令；通过地址线指明要操作的设备；通过数据线来取出（输入）数据或者放入（输出）数据。
2. I/O 逻辑
    负责接收和识别 `CPU` 的各种命令（如地址译码），并负责对设备发出命令
3. 控制器与设备的接口
    用于实现控制器与设备之间的通信；控制器通过此接口向设备发出控制信息

此外，由于**一个 I/O 控制器可能会对应多个设备**，因此数据寄存器、控制寄存器和状态寄存器可能有多个（如：每个控制/状态寄存器对应一个具体的设备），且这些寄存器都要有相应的地址，才能方便 `CPU` 操作。有的计算机会让这些寄存器占用内存地址的一部分，称为**内存映像 I/O**；另一些计算机则采用 I/O 专用地址，即**寄存器独立编址**。

### 内存映像 I/O 和寄存器独立编址
![](../img/05-设备管理/250217-203837.png)

内存映像 I/O：控制器中的寄存器**与内存地址统一编址**；优点是简化了指令，可以采用对内存进行操作的指令来对控制器进行操作。
寄存器独立编址：控制器中的寄存器使用单独的地址（即不和内存地址统一编址）；缺点是需要设备专门的指令来实现对控制器的操作，不仅要指明寄存器的地址，还要指明（设备）控制器的编号。

## I/O 控制方式
![](../img/05-设备管理/250217-204549.png)
![](../img/05-设备管理/250217-215535.png)

### 程序直接控制方式
![](../img/05-设备管理/250217-204929.png)
1. `CPU` 向控制器发出读指令。于是设备启动，并且设置状态寄存器为 1（表示未就绪）
2. **轮询检查控制器的状态**。（其实就是在不断地执行程序的循环，若状态为一直是 1，说明设备还没有准备好要输入的数据，于是 `CPU` 会不断地轮询）（2 比 3 先执行是因为 `CPU` 的速度比指令经过 I/O 逻辑和设备处理并返回数据的过程要快。）
3. 输入设备准备好数据后将数据传给控制器，并报告自身状态
4. 控制器将输入的数据放到数据寄存器中，并将状态改为 0（表示已就绪）
5. `CPU` 发现设备已就绪，即可将数据寄存器中的内容读入 `CPU` 的寄存器中，再把 `CPU` 寄存器中的内容放入内存
6. 若还要继续读入数据，则 `CPU` 继续发出读指令
![](../img/05-设备管理/250217-210049.png)
- 数据从设备到内存需要经过 `CPU`
- `CPU` 干预的频率
    很频繁，I/O 操作开始之前、完成之后需要 `CPU` 介入，并**在等待 I/O 完成的过程中 `CPU` 需要不断地轮询检查**。
- 数据传送的单位
    每次读/写一个**字**
- 数据的流向
    读操作（数据输入）：I/O 设备 -> `CPU`（寄存器） -> 内存；写操作（输入输出）：内存 -> `CPU` （寄存器）-> I/O 设备。每个字的读/写都需要 `CPU` 的帮助。
- 主要优缺点
    优点：实现简单。在读/写指令之后，加上实现循环检查的一系列指令即可（因此才称为“程序直接控制方式”）。
    缺点：**`CPU` 和 I/O 设备只能串行工作，`CPU` 需要一直轮询检查，长期处于“忙等”状态**，`CPU` 和 I/O 设备的利用率低。

### 中断驱动控制方式
![](../img/05-设备管理/250217-211153.png)
- 引入中断机制。
- 在 `CPU` 发出读/写命令后，**可将等待 I/O 的进程阻塞，先切换到别的进程执行**
- 当 I/O 完成后，**控制器会向 `CPU` 发出一个中断信号**
- `CPU` 检测到中断信号后，会保存当前进程的运行环境，转去**执行中断处理程序处理该中断**。处理中断的过程中，`CPU` 从控制器读取**一个字**的数据传送到 `CPU` 寄存器，再写入内存
- 接着，`CPU`恢复等待 I/O 的进程（或其他进程）的运行环境，然后继续执行。

注意点：
1. **`CPU` 会在每个指令周期的末尾检查中断**；
2. 中断处理过程需要保存、恢复进程的运行环境，这个过程是需要一定时间开销的。
因此，**如果中断发生频率太高，也会降低系统性能**。

- `CPU` 干预频率
    每次 I/O 操作开始之前、完成之后需要 `CPU` 介入。等待 I/O 操作完成的过程中 `CPU` 可以切换到别的进程执行。
- 数据传送的单位
    每次读/写一个**字**
- 数据的流向
    读操作：I/O 设备 -> `CPU` -> 内存；
    写操作：内存 -> `CPU` -> I/O 设备
- 主要缺点和主要优点
    优点：与“程序直接控制方式”相比，在“中断驱动方式”中，I/O 控制器会通过中断信号主动报告 I/O 已完成，`CPU` 不再需要不停轮询。**`CPU` 和 I/O 设备可并行工作**，`CPU` 利用率得到明显提升。
    缺点：每个字在 I/O 设备与内存之间的传输，还需要经过 `CPU` 。而**频繁的中断处理会消耗较多的 `CPU` 时间**。

### `DMA`方式
- `DMA`方式（Direct Memory Access，**直接存储器存取**）
- **主要用于块设备的 I/O 控制**
- 改进的点：
  1. **数据传送单位是“块”**，不再是一个字
  2. 数据的流向是**从设备直接放入内存**，或者**从内存直接到设备**，不再需要经过 `CPU`
  3. 仅在传送一个或多个数据块的开始和结束时，才需要 `CPU` 干预
![](../img/05-设备管理/250217-213342.png)

* `DMA` 控制器（一种 I/O 控制器）
  1. 组成：主机-控制器接口、I/O 控制逻辑、块设备-控制器接口、相关寄存器
  2. 控制器与内存有直接的总线连接，从而数据不需要经过 `CPU`
  3. `DMA` 在读/写数据时也是一个字一个字地读/写，只有当要求的数据量都存储在数据寄存器中时才会传输给内存或设备。
![](../img/05-设备管理/250217-214155.png)
![](../img/05-设备管理/250217-214444.png)
**`CPU` 每发出一条 I/O 指令，只能读/写一个或多个连续的数据块**。如果要读/写多个离散存储的数据块，或者要将数据分别写到不同的内存区域时，`CPU` 要分别发出多条 I/O 指令，进行多次中断处理才能完成。

## I/O 软件层次结构
![](../img/05-设备管理/250217-220003.png)
设备独立性软件、设备驱动程序、中断处理程序属于操作系统**内核**部分；即“**I/O 子系统**”或“**I/O 核心子系统**”。
![](../img/05-设备管理/250217-230714.png)

### 设备独立性软件
![](../img/05-设备管理/250217-220427.png)
设备独立性软件也称为*系统调用处理层*，又称设备无关性软件。**与设备的硬件特性无关的功能几乎都在这一层实现**：
1. 向上层提供统一的调用接口（如 `read/write` 调用）
2. 设备的保护。原理类似于文件保护，设备被看作是一中特殊的文件，不同用户对各个文件的访问权限是不一样的。同理，对设备的访问权限也不一样。
3. 差错处理。设备对立性软件需要对一些设备的错误进行处理。
4. 设备分配与回收。
5. 数据缓冲区管理。可以通过缓冲技术屏蔽设备之间数据交换单位大小和传输速度的差异。
6. 建立逻辑设备名（用户看到的设备名）到物理设备名的映射关系；根据设备类型选择调用相应的驱动程序。设备独立性软件需要通过“**逻辑设备表（LUT，Logical Unit Tabel）**”，来确定逻辑设备对应的物理设备，并找到该设备对应的设备驱动程序。
![](../img/05-设备管理/250217-225327.png)
逻辑设备表的管理方式类似与文件目录中的一级目录和两级目录。
- 不同类型的 I/O 设备需要不同的驱动程序：不同设备的内部硬件特性、电子部件（I/O控制器）可能不同，这些特性只有厂家才知道，因此厂家须提供与设备相对应的驱动程序，`CPU` 执行驱动程序的指令序列，来完成设置设备寄存器，检查设备状态等工作。
- 设备独立性软件需要调用设备驱动程序来实现对相应设备的控制

## 输入/输出管理

### 输入/输出应用程序接口
**用户层的应用程序无法用一个统一的系统调用接口来完成所有类型设备的 I/O**。如，块设备可以指定读取数据的长度、起始地址，因为块设备可寻址；但是字符设备不可寻址，且每次只能读取一个字符，因此对它们的操作需要提供不同的系统调用。

![](../img/05-设备管理/250217-231611.png)
1. 字符设备接口：
    `get/put` 系统调用：向字符设备读/写一个字符
2. 块设备接口：
    `read/write`,`seek`系统调用：`seek` 用于修改读写指针位置
3. 网络设备接口（又称网络套接字`socket`接口）：
    `socket` 系统调用：创建一个网络套接字，需要指明网络协议（`TCP/UDP`）;（申请一片内核空间，用于发送和接收数据）
    `bind`：将套接字绑定到某个**本地端口**；
    `connect`：将套接字连接到远程地址；（通过端口号和 `IP` 地址建立两个套接字的连接）
    `read/write`：从套接字读/写数据
![](../img/05-设备管理/250217-232455.png)
4. 阻塞与非阻塞 I/O
![](../img/05-设备管理/250217-232855.png)

### 假脱机技术 —— 用户层软件
![](../img/05-设备管理/250219-205511.png)
![](../img/05-设备管理/250219-212256.png)
- 假脱机技术一般都需要通过与磁盘相关的设备独立性软件来实现，因此处于用户层软件（用户层软件不属于 I/O 核心子系统）。
1. 什么是脱机技术
    手工操作阶段：主机直接从 I/O 设备获取数据，由于设备速度慢，主机速度块。人机速度矛盾明显，主机要浪费很多时间来等待设备。
    批处理阶段：引入了**脱机技术/输出技术**（用磁带完成）。**脱机是指脱离主机的控制进行输入/输出操作**。引入脱机技术后，缓解了 `CPU` 与慢速 I/O 设备的速度矛盾。另一方面，即使 `CPU` 在忙碌，也可以提前将数据输入到磁带；即使慢速的输出设备正在忙碌，也可以提前将数据输出到磁带。
![](../img/05-设备管理/250219-205913.png)
2. 假脱机技术的实现原理
![](../img/05-设备管理/250219-210341.png)
   - 又称为“SPOOLing”技术，用软件的方式模拟脱机技术
   - 输入井和输出井是**在磁盘上**开辟出来的两个存储区域
   - 要实现 `SPOOLing` 技术，必须要有多道程序技术的支持。（输出进行和输入进程需要和用户进程并发地执行）
   - “输入进程”模拟脱机输入时的外围控制机，“输出进程”模拟脱机输出时的外围控制机。
   - 输入缓冲区和输出缓冲区是在**内存中**的缓冲区；在输入进程的控制下，“输入缓冲区”用于暂存从输入设备输入的数据，之后再转存到输入井中；在输出进程控制下，“输出缓冲区”用于暂存从输出井传输来的数据，之后再传送到输出设备上。
   - 实现**预输入，缓输出**

### I/O 调度 —— 设备独立性软件
- 指用某种算法确定一个好的顺序来处理各个 I/O 请求。如磁盘调度（先来先服务算法、最短寻道优先算法、`SCAN`算法、`LOOK` 算法等）。当多个磁盘 I/O 请求到来时，用某种调度算法确定满足 I/O 请求的顺序。

### 设备的分配与回收 —— 设备独立性软件
![](../img/05-设备管理/250219-212419.png)

1. 设备分配时应考虑的因素
    1.1 设备的固有属性：独占设备、共享设备、虚拟设备。
![](../img/05-设备管理/250219-212755.png)
    1.2 设备分配算法：先来先服务、优先级高者优先、短任务优先...
    1.3 设备分配中的安全性：安全分配方式（不会死锁）、不安全分配方式（可能导致死锁）
![](../img/05-设备管理/250219-213039.png)
2. 静态分配与动态分配
    静态分配：进程运行前为其分配全部所需资源，运行结束后归还资源；（破坏了“请求和保持”条件，不会发生死锁）
    动态分配：进程运行过程中动态申请设备资源；（并不是运行前就需要得到全部的资源）

1. 输入进程请求输入数据：从空缓冲队列中取出一块作为收容输入数据的工作缓冲区（`hin`）。充满数据后将缓冲区挂到输入队列队尾。
2. 计算进程想要取得一块输入数据：从输入队列中取得一块充满数据的缓冲区作为“提取输入数据的工作缓冲区（`sin`）”。缓冲区读空后挂到空缓冲区队列。
3. 计算进程想要将准备好的数据冲入缓冲区：从空缓冲队列中取出一块作为“收容输出数据的工作缓冲区（`hout`）”。数据充满后将缓冲区挂到输出队列队尾。
4. 输出进程请求输出数据：从输出队列中取得一块充满数据的缓冲区作为“提取输出数据的工作缓冲区（`sout`）”。缓冲区读空后挂到空缓冲区队列。

### 一次读/写需要的时间
= 寻道时间 + 延迟时间 + 传输时间
1. 寻道时间：现在的移动硬盘移动一个磁道大约需要 0.2 ms，磁臂启动时间约为 2ms。
2. 延迟时间
![](../img/05-设备管理/250220-210259.png)
3. 传输时间
![](../img/05-设备管理/250220-210448.png)
其中，延迟时间和传输时间都与磁盘转速有关，且为线性相关。而转速是硬件的固有属性，因此**操作系统也无法优化延迟时间和传输时间。但是操作系统的磁盘调度算法会直接影响寻道时间**。

### 磁盘调度算法
指标是移动磁头所花的时间。

1. 先来先服务算法（`FCFS`）

- 缺点：如果有大量进程竞争使用磁盘，请求访问的磁道很分散，则 `FCFS` 在性能上很差，寻道时间长。

2. 最短寻找时间（`SSTF`）
![](../img/05-设备管理/250220-211535.png)
- 贪心算法的思想，能保证眼前最优，但**无法保证总的寻道时间最短**。

## 减少磁盘延迟时间的方法
![](../img/05-设备管理/250220-212854.png)
- 磁头读入一个扇区数据后需要一小段时间处理，如果逻辑上相邻的扇区在物理上也相邻，则读入几个连续的逻辑扇区，可能需要很长时间

![](../img/05-设备管理/250220-214724.png)

1. 减少延迟时间的方法：交替编号
    若采用交替编号的策略，即让逻辑上相邻的扇区在物理上有一定的间隔，可以使读取连续的逻辑扇区所需要的延迟时间更小。
2. 方法2：磁盘地址结构的设计
    是（**柱面号，盘面号，扇区号**），而不是（盘面好，柱面号，扇区号）
![](../img/05-设备管理/250220-213646.png)
![](../img/05-设备管理/250220-213750.png)
    因此，读取连续地址时，采用（柱面号，盘面号，扇区号）的地址结构可以减少磁头移动消耗的时间。
1. 方法3：错位命名
![](../img/05-设备管理/250220-214114.png)
    原因与交替编号时出现的问题一样。（所有盘面都是一起连轴转的）
![](../img/05-设备管理/250220-214630.png)

## 固态硬盘 `SSD`
![](../img/05-设备管理/250220-223936.png)
- 原理：基于闪存技术 `Flash Memory`，属于电可擦除 `ROM`，即 `EEPROM`
- 组成：存储介质 + 闪存翻译层（翻译逻辑块号，找到对应的页）

![](../img/05-设备管理/250220-224214.png)
- **固态硬盘的读写单位为页**，相当于磁盘中的扇区；而固态硬盘中的块相当于磁盘中的磁道
- **固态硬盘以块为单位进行擦除**，不为空的块需要被擦除后才能写入新的数据
- 当需要将数据写入一个未被装满的块时，需要将该块中原本的数据拷贝到一个空块中并同时写入需要写的数据。此时，闪存翻译层应修改逻辑映射对应的物理地址。（因此，固态硬盘通常是读快写慢）
