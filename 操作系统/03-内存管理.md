### 内存的概念和作用

* 内存可以存放数据
    - 由于 CPU 和硬盘（外存）之间的速度矛盾，**程序执行前需要先放到内存中才能被 CPU 处理**
    - 存储数据的最小单元即为存储单元
    - 内存编址从 0 开始，每个地址对应一个存储单元；如果计算机“**按字节编址**”，则每个存储单元大小为 1 个字节，即 1B(1B yte)，即**8个二进制位**。“**按字编址**”——需要根据 CPU 的字长来定。
* 常用单位：
    - $2^{10} = 1 K$
    - $2^{20} = 1 M$
    - $2^{30} = 1 G$
* 物理地址和逻辑地址
    - 物理地址即绝对地址
    - 逻辑机制即相对地址

### 指令的工作原理
![](../img/03-内存管理/250208-110647.png)
    1. 代码 `x = x + 1` 被编译成数个用于 CPU 实际操作的指令。在上图中指令由 **操作码 + 操作地址1 + 操作地址2** 组成（不一定是这样）
    2. 首先，CPU 根据第一条指令的操作码执行数据传送指令，将位于 01001111 处的变量 x 加载到地址为 00000011 的寄存器中；
    3. 执行第二条加法指令，将地址为 00000011 的寄存器中的数值加 1
    4. 将存储在上述寄存器中的加法指令运算结果存入地址为 01001111 的内存中。
![](../img/03-内存管理/250208-112537.png)
当进程的相关内容从地址 0 开始连续存放，上述指令可以正确执行——指令 0 将数据正确地存放到了地址为 79 的存储单元。然而，**指令中指明的是逻辑地址**，当进程的存储并不是从地址 0 开始时，如果按物理地址进行操作，则会导致错误。
![](../img/03-内存管理/250208-112817.png)

### 装入的三种方式
**实现逻辑地址->物理地址**

1. 绝对装入
![](../img/03-内存管理/250208-113127.png)
   - 物理地址确定时间：编译时
   - 要求：需要提前知道装入模块的起始地址
   - 缺点：绝对装入只适用于单道程序环境(无操作系统)；灵活性低（当前设备的起始地址为 100，换到其他设备则不一定可行）
2. 静态重定位（又称为**可重定位装入**）
![](../img/03-内存管理/250208-114059.png)
   - 物理地址确定时间：装入时确定 
   - 要求：一个作业装入内存时，**必须分配其要求的全部内存空间（连续内存空间）**
   - 缺点：如果没有足够的内存，就不能装入该作业。作业一旦进入内存后，**在运行期间就不能再移动，也不能再申请内存空间**。
3. 动态重定位（又称为**动态运行时装入**）
![](../img/03-内存管理/250208-114908.png) 
   - 物理地址确定时间：把地址转换（逻辑->物理）推迟到程序真正要执行时才进行，因此装入内存后的所有地址依然是逻辑地址
   - 要求：需要一个**重定位寄存器**的支持；**物理地址 = 重定位寄存器值 + 指令中的逻辑地址**
   - 优点：
     1. 采用动态重定位时**允许程序在内存中发生移动**。（只需要改变重定位寄存器中的值即可）
     2. 可将程序分配到**不连续的存储区中**
     3. 在程序运行前只需装入它的**部分代码即可投入运行**，然后在程序运行期间，**根据需要动态申请分配内存**
     4. **便于程序段的共享，可以向用户提供一个比存储空间大得多的地址空间**。

## 内存空间的分配与回收
### 连续分配管理方式
![](../img/03-内存管理/250208-192622.png)
连续分配：**指为用户进程分配的必须是一个连续的内存空间**，连续分配管理方式又可以分为：单一连续分配、固定分区分配和动态分区分配。

1. 单一连续分配
![](../img/03-内存管理/250208-155256.png)
   * 内存被分为**系统区**和**用户区**
   * 内存中只能有一道用户程序
   * 优点：实现简单；**无外部碎片**；可以采用覆盖技术扩充内存；不一定需要采用内存保护
   * 缺点：只能用于**单用户、单任务的操作系统中**；**有内部碎片**；存储器利用率极低
2. 固定分区分配
![](../img/03-内存管理/250208-160044.png)
   * 固定分区分配根据分区大小是否一致可以划分为：分区大小相等、分区大小不等两种分配方式
   * 内存同样被分为**系统区**和**用户区**，其中用户区（用户空间）被划分为**若干个固定大小的分区**，在**每个分区中只装入一道作业**。这样就形成了最早的、最简单的一种可以运行**多道程序**的内存管理方式。
   * 通过**分区说明表**来实现各个分区的分配与回收
   * 优点：实现简单，无外部碎片
   * 缺点：1. 当用户程序太大时，可能所有的分区都不能满足需求，此时不得不采用覆盖技术来解决，但这又会降低性能；2. 会产生内部碎片，内存利用率低
![](../img/03-内存管理/250208-160555.png)
3. 动态分区分配
![](../img/03-内存管理/250208-185038.png)
动态分区分配又称为**可变分区分配**。这种分配方式**不会预先划分内存分区，而是在进程装入内存时根据进程的大小动态地建立分区**，并使分区的大小正好适合进程的需要。
* 系统记录内存使用情况所用的数据结构
    1. 空闲分区表
    2. 空闲分区链
![](../img/03-内存管理/250208-185623.png)
* 分区的分配方式（存在多个分区满足分配要求时）
    根据**动态分区分配算法**从空闲分区表（空闲分区链）中选择一个分区分配给该作业。
![](../img/03-内存管理/250208-192732.png)
![](../img/03-内存管理/250208-195355.png)
    1. 首次适应算法（First Fit）
        * 算法思想：每次都**从低地址开始查找**，找到第一个能满足分配分区大小的空闲分区。
        * 实现：**空闲分区以地址递增的次序排列**。每次分配内存时顺序查找空闲分区链（空闲分区表）。
        * 由于分配结束后空闲分区的起始地址关系一般没有变化，因此只需要修改在空闲分区表（链）中对应分区的起始地址和分区大小即可（不需要调整空闲分区表（链）中元素的排列顺序）。
    2. 最佳适应算法（Best Fit）
![](../img/03-内存管理/250208-194306.png)
        * 算法思想：为了保证当“大进程”到来时能够连续的大片空间，可以尽可能地留下大片地空闲区，即**优先使用更小的空闲区**。
        * 实现：空闲分区**按容量递增次序链接**
        * 分配后，**一般需要调整空闲分区链（表）中元素的排列顺序、分区大小和起始地址**。
    3. 最坏适应算法（Worst Fit）
![](../img/03-内存管理/250208-194532.png)
        * 如果空闲分区表（链）中第一个分区都不能够满足分配需求，则后续空闲区均不能满足要求。
        * 分配结束后也需要重新排列空闲分区表（链）中的元素顺序
    4. 邻近适应算法（Next Fit）
![](../img/03-内存管理/250208-195124.png)
        * 类似于首次适应算法，分配结束后一般无需调整元素的顺序
* 进行分区分配和回收操作的方式
    1. 分配
![](../img/03-内存管理/250208-185919.png)
    从 1 号分区分配 4MB 大小内存给进程 5，分配后更新空闲分区表（空闲分区链）中 1 号分区的**起始地址和分区大小**；如果分配给进程 5 的分区大小正好为进程 5 所需的空间大小，则需要将对应分区从空闲分区表（空闲分区链）中**删除**
    1. 回收
![](../img/03-内存管理/250208-190601.png)
        1. 情况一：回收区前存在相邻的空闲分区
        2. 情况二：回收区后存在相邻的空闲分区
            1 和 2：合并；调整对应相邻分区的起始地址或分区大小
        3. 情况三：回收区前后存在相邻的空闲分区
            合并；调整空闲分区表（空闲分区链）中的空闲分区的个数（减少 1）；同时还需更新合并后空闲分区的起始地址和分区大小
        4. 情况四：回收区前后都不存在相邻的空闲分区
            增加空闲分区表（空闲分区链）中空闲分区的个数（增加 1）；同时还需更新合并后空闲分区的起始地址和分区大小（为当前回收分区的起始地址和分区大小）
        * 各表项的顺序不一定按照地址递增顺序排列，具体的排列方式需要依据动态分区分配算法来确定。
* 动态分区分配**没有内部碎片**，但**有外部碎片**（内部碎片：分配给某进程的内存区域中，如果有些部分没有用上；外部碎片：指内存中的某些空闲分区由于太小而难以利用）
![](../img/03-内存管理/250208-191822.png)
中级调度是：...
动态分区分配应使用动态运行时装入的方式，以动态调整进程地址；“紧凑”之后需要对应修改进程的起始地址。（动态调整进程运行地址是通过在进程上 CPU 运行前调整位于 `PCB` 中的进程起始地址来实现的，该地址会加载到重定位寄存器（基址寄存器）中）

    * 基本地址变换机构
        基本地址变换结构是用于实现逻辑地址到物理地址转换的一组**硬件机构**
![](../img/03-内存管理/250209-112256.png)
        1. 逻辑地址到物理地址的变换过程：
![](../img/03-内存管理/250209-114457.png)
            * 进程切换相关的内核程序负责恢复进程运行环境
            * 进程运行环境（进行运行相关信息）被保存在 `PCB` 中
            * `PCB` 被保存在内存中的**系统区**
            * 恢复时，将 `PCB` 中相关信息加载到（CPU的）寄存器中；例如：页表寄存器加载页表的起始地址和页表长度、程序计数器 `PC` 加载指向**下一条**指令的*逻辑地址*。
![](../img/03-内存管理/250209-112623.png)
            * `PC` 对应指令从逻辑地址到物理地址的转换过程：
![](../img/03-内存管理/250209-113306.png)
                1. 根据逻辑地址计算出页号、页内偏移量（需要知道页面的大小/内存块大小）
                2. **判断页号是否越界**（与页表寄存器中的页表长度进行比较）
                3. 查询页表，找到页号对应的页表项，确定页面存放的内存块号（页表项地址 = 页号 * 页表项长度 + 页表始地址）
                4. 用内存块号和页内地址偏移量得到物理地址(内存块号实际物理地址 = 内存块号 * 内存块大小，块号物理地址与偏移量拼接可得目标物理地址)
                5. 访问目标内存单元
                * 需要两次访问内存：1. 访问页表；2. 访问目标物理地址
![](../img/03-内存管理/250209-114700.png) 
                * 页式管理中地址是**一维**的，即只需要知道逻辑地址就能得到对应的物理地址

2. 基本分段存储管理
    与“分页”最大的区别就是：离散分配时所分配地址空间的基本单位不同。
![](../img/03-内存管理/250209-163142.png)
    * 什么是分段
        - 进程的地址空间被**按照程序自身的逻辑关系**划分为若干个段
        - 每段都从 0 开始编址（对应段内偏移量）
        - 以段为段位进行分配，**每个段在内存中占据连续空间**，但**各段之间可以不相邻**
![](../img/03-内存管理/250209-163243.png)
        - 段号的位数决定了每个进程最多可以被分成几个段
        - 段内地址位数决定了每个段的最大长度是多少
![](../img/03-内存管理/250209-163619.png)
    * 什么是段表
        - 段号同样也是可以隐含的（因为段表项的长度相同）
![](../img/03-内存管理/250209-163807.png)
    * 如何实现地址变换
        通过逻辑地址可以得到 段号 + 段内地址
![](../img/03-内存管理/250209-164525.png)
        进程加载时将 `PCB` 中的相关信息加载到寄存器中，段表寄存器将存入段表始地址和段表长度。
![](../img/03-内存管理/250209-164615.png)
        在第四步中，需要再次检查段内地址是否在对应段内产生了越界。这在分页方式中是不需要判断的（分页方式中页内地址的位数和页面的大小是一致的，每个页面的大小也是一致的，不会导致越界）。
![](../img/03-内存管理/250209-164755.png)
    * 分段、分页管理的对比
![](../img/03-内存管理/250209-163041.png)
        1. 页是信息的物理单元；段是信息的逻辑单元
        2. 分页是对用户不可见的；分段对用户是可见的
        3. 页的大小固定且由系统决定；段的长度却不固定，决定于用户编写的程序
        4. 分页的用户进程地址空间是一维的；分段的用户进程地址空间是二维的，需要知道段号和段内地址才能实现逻辑地址与物理地址的转换
![](../img/03-内存管理/250209-165117.png)
        1. **分段比分页更容易实现信息的共享和保护**

## 内存空间的扩容
![](../img/03-内存管理/250208-132850.png)
![](../img/03-内存管理/250209-174437.png)

### 覆盖技术
![](../img/03-内存管理/250208-131125.png)
* 覆盖技术思想：将程序分为多个**段**（多个**模块**），常用的段常驻内存，不常用的段在需要时调入内存
* 内存中分为**一个“固定区”**和**若干个“覆盖区”**
* 需要常驻内存的段放在固定区，**调入后就不再调出（除非运行结束）**；不常用的段放在覆盖区，**需要用时调入内存，用不到时调出内存**

![](../img/03-内存管理/250208-131818.png)
* 运行上述程序时，采用覆盖技术后所需内存由原本的 52K -> 30K，使所需运行内存减小，从逻辑上实现了扩容
* **采用覆盖技术必须由程序员声明覆盖结构，因此对用户不透明**

### 交换技术
也称为对换技术
* 交换技术思想：内存空间紧张时，系统将内存中某些**进程***暂时换出外存*，把外存中某些已具备运行条件的进程*换入内存*（**进程在内存与外存（硬盘）间动态调度**），因此从逻辑上实现了内存扩容
* **处理机调度中的中级调度**是实现交换技术的一种调度策略
* 进程被换出到外存时，**其 `PCB` 仍然被保留在内存中（被插入到挂起队列中）**，以备后续的换入操作。（`PCB`可被用来保存换出数据保留在外存的地址信息，因此 `PCB` 需要常驻内存）
![](../img/03-内存管理/250208-134046.png)
* 补充-进程的七状态模型
![](../img/03-内存管理/250208-134219.png)
* 换出进程的位置、时间、选择（`PCB` 会常驻内存，不会被换出外存）
    1. 位置：换出进程被保存在外存的对换区
    2. 时间：交换通常发生在许多进程运行且内存吃紧时
    3. 选择：可以优先换出阻塞进程、优先级低的进程等，根据实际交换策略确定
![](../img/03-内存管理/250208-134651.png)

### 虚拟存储技术
#### 基本概念
![](../img/03-内存管理/250209-174519.png)
![](../img/03-内存管理/250209-175309.png)
**基于局部性原理**

1. 传统存储管理方式的特征、缺点
![](../img/03-内存管理/250209-175651.png)
    - **作业必须一次性全部装入内存后才能开始运行**
    - 一旦作业被装入内存中，就会**一直驻留在内存中，直至作业结束**。
2. 局部性原理
    - 时间局部性
    - 空间局部性
    - 基于局部性原理实现高速缓存技术
3. 虚拟内存的定义和特征
![](../img/03-内存管理/250209-180042.png)
    - 多次性：无需在作业运行时一次性全部装入内存，而是允许被分成多次调入内存
    - 对换性：在作业运行时无需一直常驻内存，而是允许在作业运行过程中，将作业换入、调出
    - 虚拟性：从逻辑上扩充了内存的容量，使用户看到的内存容量远大于实际的容量，其实实际内存容量是未发生变化的。
4. 如何实现虚拟内存技术
![](../img/03-内存管理/250209-180446.png)
    - 在非连续分配存储管理三种方式的基础之上，虚拟内存的实现也同样可以分为三种。
    - 建立在离散分配的内存管理方式上（连续分配方式要求进程处于内存中的一片连续区域，这不利于虚拟技术中的换入、调出）
    - 操作系统需要实现相关功能：请求调页（调段）功能、页面（段）置换功能

#### 请求分页管理方式
![](../img/03-内存管理/250209-184324.png)
![](../img/03-内存管理/250209-184235.png)

1. 页表机制
    - 与基本分页存储管理的页表相比，请求分页管理方式的页表在原来基础上增加了：
        1. 状态位：表明对应页面是否被调入内存
        2. 访问字段：用于供置换算法选择换出页面时的参考（可记录最近被访问的次数或时间）
        3. 修改位：记录页面被调入内存后是否被修改过（当被调出的页面没有没有被修改时就不用再浪费时间写回外存）
        4. 外存地址：页面在外存中的存放位置
![](../img/03-内存管理/250209-184840.png)
2. 缺页中断机构
    为实现请求调页功能系统中需要引入缺页中断机构
![](../img/03-内存管理/250209-185117.png)
    - 在**请求分页系统中**，当访问的页面不在内存时产生**缺页中断**，操作系统的缺页中断处理程序处理中断，进程被阻塞（放入阻塞队列），调页完成后再将其唤醒，放回就绪队列
    - 在页面调入过程中如果内存中有空闲块，则为进程分配一个空闲块（修改对应的页表项）
    - 在页面调入过程中如果内存中没有空闲块，则由**页面置换算法**选择一个页面淘汰（根据被修改情况判断是否需要写入外存），修改对应的页表项。
    - 页面的换入、换出需要进行外存（磁盘）I/O操作，会有较大的开销
![](../img/03-内存管理/250209-185939.png)
    - 缺页中断属于内终端
    - 一条指令的执行期间可能产生多次缺页中断
3. 地址变换机构
![](/img/03-内存管理/250209-190044.png)
    - 与基本分页存储管理的主要区别：
        1. 可能需要进行请求调页（通过查找页表项状态位进行判断）
        2. 可能需要页面置换（产生缺页中断，同时内存中无空闲块）
        3. 需要修改请求页表中的新增表项
![](../img/03-内存管理/250209-190421.png)
    - 缺页时，换入的页表项需要加入到快表和慢表中，并且直接通过快表访问对应内存
    - 需要及时更新快表中的页表项
![](../img/03-内存管理/250209-190754.png)
    - 在具有快表机构的请求分页系统中，访问一个逻辑地址时，若发生缺页，则地址变换的步骤是：
        1. 查快表，未命中 ->
        2. 查慢表，发现未调入内存 ->
        3. 产生缺页中断，调页（**调入页面的对应表项会直接加入快表**）->
        4. **查快表**，命中 ->
        5. 访问目标内存单元

#### 页面置换算法
减少因换入、换出页面导致的外存（磁盘）I/O调用，**追求更少的缺页率**。
![](../img/03-内存管理/250209-191732.png)
![](../img/03-内存管理/250209-195238.png)

1. 最佳置换算法（OPT）
![](../img/03-内存管理/250209-192339.png)
    - 发生缺页中断时未必发生页面置换
    - 在预知页面访问序列的情况下，根据后续最晚需要访问的页面来进行页面的置换
    - **最佳置换算法可以保证最低的缺页率**，但实际上，只有在进程执行的过程中才能知道接下来会访问到的是哪个页面。操作系统无法提前预知页面访问序列，因此，**最佳置换算法是无法实现的**，仅理论。
2. 先进先出置换算法（FIFO）
![](../img/03-内存管理/250209-192924.png)
    - 只有 FIFO 算法会产生 Belady（贝拉迪）异常
    - 实现简单但是算法性能差
3. 最近最久未使用置换算法（LRU）
![](../img/03-内存管理/250209-193305.png)
    - 通过访问字段记录该页面自上次被访问以来所经历的时间
    - 性能好，在这些算法中最接近最佳置换算法
    - 实现困难，开销大
4. 时钟置换算法（CLOCK）
![](/img/03-内存管理/250209-193921.png)
    - 考虑一个页面最近是否被访问过
    - 当前指针处访问位为 1 时将其置为 0；当为 0 时该页面被换出，并将换入后的页面置为 1
    - 完成置换后将当前指针指向下一个位置
    - 最多会经过两轮扫描（当循环队列中全部元素都被标记为 1 时）
5. 改进型的时钟置换算法
![](../img/03-内存管理/250209-194442.png)
    - 在 CLOCK 算法基础上进一步考虑页表是否被修改过，优先选择没有被修改过的页面进行置换
    - 淘汰一个页面时最多需要四轮扫描
    - 置换优先级：最近没有被访问且没有被修改的页面 > 最近没有被访问但被修改的页面 > 最近被访问且没有被修改的页面 > 最近被访问且被修改的页面

#### 页面分配策略
![](../img/03-内存管理/250209-204107.png)
![](../img/03-内存管理/250209-204041.png)

1. 驻留集
    - 驻留集：指**请求分页存储管理**中给进程分配的**物理块**的集合
    - 考虑一个极端情况，若某进程共有 100 个页面，则该进程的驻留集大小为 100 时进程可以全部放入内存，运行期间不可能再发生缺页；若驻留集的大小为 1，则进程运行期间必定会极频繁地缺页
2. 页面分配、置换策略
![](../img/03-内存管理/250209-204809.png)
    - 分配策略：从驻留集大小是否可变，可以分为固定分配和可变分配
    - 置换策略：从发生缺页是是否只能从进程自身的物理块进行置换，可以分为局部置换和全局置换
    - 不存在固定分配全局置换策略，因此可以组合成：固定分配局部置换策略、可变分配局部置换策略、可变分配全局置换策略
![](../img/03-内存管理/250209-205209.png)
