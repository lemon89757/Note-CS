#### 定义
1. 程序：
   * 一个指令序列
   * 程序的代码放在代码段内，程序运行过程处理的数据放在数据段内（如变量） todo: 程序包含哪些段
2. 进程：
   * 进程、进程实体/进程映像（包含PCB、程序段和数据段）
   * 一般情况下，把进程实体简称为进程。例如，创建进程，实质上是创建进程实体中的PCB；而撤销进程，实质上是撤销进程实体中的PCB。**PCB是进程存在的唯一标志**。但是严格来说，进程和进程实体并不一样，**进程实体是静态的，进程则是动态的**。
   * **进程定义**：进程是进程实体的运行过程（强调动态性），是系统进行资源分配和调度的一个独立单位。
3. 进程和程序的区别和联系：
   - 进程是动态的，程序是静态的
   - 进行具有独立性，能并发执行，程序不能并发执行
   - 组成不同。进程包含PCB、程序段和数据段；程序包含数据和指令代码
   - 程序是一个包含了所有指令和数据的静态实体。本身除占用磁盘的存储空间外，并不占用系统如CPU，内存等运行资源
   - 进程会占用系统如CPU、内存等运行资源
   - 一个程序可以启动多个进程来共同完成
   - 进程不能脱离具体程序而虚设，程序规定了相应进程所要完成的动作

#### 特征
![](../img/02-进程管理/250525-223259.png)
* 动态性
  进程是程序的一次执行过程，是动态地产生、变化和消亡的
* 并发性
  内存中有多个进程实体，各进程可并发执行
* 独立性
  进程是能独立运行、独立获取资源、独立接受调度的基本单位
* 异步性
  各进程按各自独立的、以不可预知的速度向前推进，操作系统要提供同步机制来解决异步问题
* 结构性
  每个进程都会配置一个PCB。结构上看，进程由程序段，数据段、PCB组成。

* 数据段

* `PCB, Process Control Block`（进程控制块）
  ![](../img/02-进程管理/250525-221904.png)
  ![](../img/02-进程管理/250525-222150.png)
  * 系统为每个运行的程序配置一个数据结构，称为 `PCB`，用来描述进程的各种信息，如程序代码存放位置
  * `OS` 根据 `PCB` 来对并发执行的进程进行控制和管理，如进程暂停时需要将其断点的处理机环境保存在 `PCB` 中；进程同步时需要访问 `PCB`
  * 包含的内容有：
    a. 进程描述信息：进程标识符PID、用户标识符UID
    b. 进程控制和管理：进程当前状态、进程优先级、代码运行入口地址、程序的外存地址、进入内存的时间等等
    c. 资源分配清单：程序段指针、数据段指针、键盘、鼠标等
    d. 处理机相关信息：各种寄存器值。当进程状态切换时，处理机状态信息都必须保存在相应的`PCB` 中，以便后期进程能重新从断点开始执行，寄存器包括：通用、地址、控制、标志寄存器、状态字等
  * `Linux` 中的 `PCB`: `task_struct` 位于 `sched.h`

### 进程的状态及转换
![](../img/02-进程管理/250525-223845.png)
![](../img/02-进程管理/250525-225008.png)
![](../img/02-进程管理/250525-225332.png)
#### 状态
  * 运行状态 —— CPU + 其他所需资源
  * 就绪状态 —— 缺 CPU + 其他所需资源
  * 阻塞状态 —— 缺 CPU + 缺其他所需资源（CPU 是计算机中最昂贵的部件，为了提高 CPU 的利用率，需要先将其他进程需要的资源分配到位，才能得到 CPU 的服务）
  ![](../img/02-进程管理/250525-224217.png)
  ![](../img/02-进程管理/250525-224320.png)

上述为三种基本状态
  * 创建状态 —— 操作系统为新进程分配资源、创建 PCB
  * 终止状态 —— 操作系统回收进程的资源、撤销 PCB
  ![](../img/02-进程管理/250525-224047.png)
  ![](../img/02-进程管理/250525-224447.png)

#### 转换
* 就绪态 -> 运行态：进程调度
* 运行态 -> 就绪态：时间片到，或CPU被其他高优先级的进程抢占（如紧急事件、中断）
* 运行态 -> 阻塞态：等待系统资源分配（进程用系统调用的方式申请某种系统资源），或等待某事件发生（主动行为）
* 阻塞态 -> 就绪态：资源分配到位，等待的事件发生（被动行为）
* 创建态 -> 就绪态：系统完成创建进程相关的工作
* 运行态 -> 终止态：进程运行结束，货运型过程中遇到不可修复的错误
![](../img/02-进程管理/250525-224835.png)
不能由阻塞态直接转换为运行态，也不能由就绪态直接转换为阻塞态，因为进入阻塞态是进程主动请求的，必然需要进程在运行时才能发出这种请求

#### 组织
可根据执行、就绪、阻塞将进程分为不同的状态类型，在单核 CPU 中，执行的进程只有一个，而其他状态下的进程存在多个。多个进程的组织方式可以有：链接方式和索引方式。链接方式将进程一个一个前后连接起来，而索引方式将进程存入表中，通过表（索引）/队列（链接）指针来找到相应的进程。

* 链接方式：
  按照进程状态将 `PCB` 分为多个队列，操作系统持有指向各个队列的指针
  ![](../img/02-进程管理/250525-225146.png)
* 索引方式：
  根据进程状态的不同，建立几张索引表，操作系统持有指向各个索引表的指针
  ![](../img/02-进程管理/250525-225240.png)

### 进程间的通信（IPC，Inter-Process Communication）
![](../img/02-进程管理/250529-224917.png)
![](../img/02-进程管理/250529-234823.png)

#### 概念
进程通信(`IPC, Inter-Process Communication`)就是指进程之间的信息交换。

- 进程间的通信需要操作系统的支持：一个进程不能直接访问另一进程的地址空间，由操作系统来实现两者的安全通信。

#### 方式
* 进程是分配系统资源的单位（包括内存地址空间），因此各进程拥有的内存地址空间相互独立。
* 为了保证安全，一个进程不能直接访问另一个进程的地址空间
* 为实现进程间的安全通信，操作系统提供了一些方法

1. 共享存储 `shared Memory`
     - 基于数据结构的共享
    ![](../img/02-进程管理/250529-230122.png)
     - 基于存储区的共享
    ![](../img/02-进程管理/250529-230346.png)
2. 消息传递
  ![](../img/02-进程管理/250529-231024.png)
     - 进程间通过**格式化的消息**`message`进行通信；
     - 使用该方式时，进程间通过操作系统提供的**发送/接收消息两个原语进行数据交换**；
     - 直接通信方式：
    ![](../img/02-进程管理/250529-231446.png)
       - 发送进程需要指定接收进程的信息；接收进程也需要指定接收哪个进程的消息；
       - **操作系统内核管理各个进程的 `PCB`**；
       - 每个进程的 `PCB` 中存在一个消息队列；
       - 发送进程通过发送原语将需要发送的消息挂到接收进程的消息队列上；接收进程通过接收原语，从自身的消息队列上取出想要接收进的程发过来的消息；
     - 间接通信方式
    ![](../img/02-进程管理/250529-232015.png)
       - 发送进程通过发送原语往内核区的某一信箱中发送数据；接收进程通过接收原语从内核区中的某一信箱中取数据；
       - 可以多个进程往同一个信箱中 `send` 消息；也可以多个进程从同一个信箱中 `receive` 消息；
3. 管道通信
   - 管道具有 `FIFO` 特性；实质是在内存中开辟一个大小固定的内存缓冲区，具有环形队列的数据结构;
  ![](../img/02-进程管理/250529-233310.png)
   - 单个管道只能采用半双工通信；
   - 对管道的互斥访问由操作系统实现
   - 管道满时，写进程被阻塞；管道空时，读进程被阻塞；
  ![](../img/02-进程管理/250529-234240.png)

   * 管道通信 `Pipe Communication`是一种在 `Unix`和类 `Unix`系统中用于进程间通信的机制
   * 可以分为：匿名管道(`Anonymous Pipe`)和命名管道(`Named Pipe`，也称为 `FIFO`管道)
   * Anounymous Pipe: 用于在具有亲缘关系的进程间通信，通常用于父子进程之间的通信；匿名管道是**单向**的，只能在一个方向上传输数据；
   * Named Pipe: 可以在没有亲缘关系的进程之间进行通信；**命名管道在文件系统中有一个名字，因此可以像文件一样打开和操作**；支持**双向**通信。

4. 信号
  - 信号（`signal`）实现进程间的通信；信号量（`semaphore`）实现进程间的同步、互斥；
  ![](../img/02-进程管理/250531-001452.png)
  ![](../img/02-进程管理/250531-010141.png)
  - 信号的作用
  ![](../img/02-进程管理/250531-001942.png)
    - 转储内存：将当前进程的内存数据存储到外存中；
  - 信号发送与保存
  ![](../img/02-进程管理/250531-002816.png)
    - 在进程控制块（`PCB`）中存在用于保存待处理信号和被阻塞信号的位向量。通过在待处理信号位向量的特定位置 1，以表示产生了该特定位所对应的信号；通过给被阻塞信号位向量的特定位置 1，以屏蔽给位对应的信号；
    - 其他进程可以通过系统调用 `kill` 来给目标进程发送特定的信号；
    - 进程之间允许发送的信号类类型是有限的；操作系统内核进程具有最高的权限；
    - 有多个进程给相同目标进程同时发送相同的信号，该信号只被记录一次；
  - 信号的处理
  ![](../img/02-进程管理/250531-004040.png)
  ![](../img/02-进程管理/250531-005322.png)
    - 处理信号的时间：**当进程从内核态转为用户态时，例行检查是否有待处理的信号**。如果有，就处理信号；（因此信号到达时并不会马上处理）
    - 待处理信号和被阻塞信号位向量相与的结果表明了需要被处理的信号，从而执行预定好的处理该信号的程序。一旦处理了某种信号，对应的 `pending` 位被重置为 0；
    - 优先处理更小的信号；
    - 进程自定义的信号处理函数只对自己有效，对其他进程无效；
  - 信号与异常
  ![](../img/02-进程管理/250531-005924.png)

- 补充：共享存储和管道通信对比
  都涉及到某种形式的“共享空间”，但具体实现和使用场景有显著区别
  1. 在实现方式上
     * 共享存储是通过在**内存**中开辟一块共享区域，多个进程可以直接访问这块内存区域来实现通信；分为匿名共享存储(通过系统调用 `shmget和shmat`创建和附加共享存储段)和命名共享存储(通过 `mmap`系统调用，可以将文件或匿名页映射到进程的地址空间，多个进程可以映射同一个文件或页，从而实现共享)。
     * 管道通信通过在**内核（缓存区）**中创建一个特殊的**文件描述符**来实现进程间的通信，数据通过这个文件描述符在进程间传输；分为匿名管道（通过 `pipe`系统调用创建）和命名管道（使用 `mkfifo`系统调用创建）
  2. 在用途上
     * 共享存储：数据直接在内存中交换，无需通过内核缓存区，适用于需要高效、低延迟、频繁数据交换的场景（例如实时数据处理）；但是需要手动处理进程间的同步问题，如使用信号量或互斥锁、需要手动管理共享内存的创建和销毁，放置内存泄露；
     * 管道通信：实现简单，适用于需要顺序、流式数据传输的场景（例如日志记录系统）；内核自动管理缓存区，无需手动同步和内存管理；数据通过内核缓存区传输，适合小数据量、低频率传输，不适合大量数据的高频传输；管道是单向的，需要双向通信时需要创建两个管道
- 补充："流" `Stream`
  * 表示数据的有序序列；可以是字节序列或字符序列，数据可以逐个字节或字符地读取或写入
  * 可以用于多种目的，如文件操作、网络通信、输入输出、内存操作（内存缓存区读写数据）等
  * 流可以是单向（只读或只写）的也可以是双向（可读可写）的
  * 实现分为低级流和高级流
    1. 低级流：直接与底层系统资源进行交互，如文件描述符、套接字等；提供基本的读写操作，通常效率较高
    2. 高级流：基于低级流，提供更高级的抽象和功能，如缓冲流（提供缓冲机制、提高读写效率）、数据流（提供更复杂的读写操作，如读写基本数据类型）
  * 与数组的对比
    1. 流的大小可以动态变化，护具可以逐个字节或字符地读取或写入
    2. 流中的数据通常是顺序访问的，不能通过索引直接访问特定位置的数据
    3. 流提供了一个抽象层（**流是一个抽象的概念**，在内存中，流的具体表示方式取决于流的用途和类型，如字节流(字节数组或动态数组)、字符流、文件流（文件描述符-Unix或文件句柄-Windows + 缓冲区）、网络流（套接字Sokect + 缓冲区）、内存流（动态扩展的字节数组）），可以用于多种数据源和目标，如文件、网络、内存等
    4. 流通常包含缓冲机制，可以提高读写效率
- 补充：上下文 `Context`
  **指执行环境的状态和相关信息**，上下文可以包括多种信息，具体取决于上下文的类型和应用场景。
  * 执行上下文
    指当前正在执行的代码的环境。在编程语言中，执行上下文通常包括：**调用栈**（记录当前函数调用的栈信息，栈段）、**局部变量**（函数中定义的变量，栈段）、**参数**（传递给当前函数的参数，值传递参数-栈段、引用传递或指针传递-参数本身在栈段，数据可能在堆段或数据段）、**返回地址**（函数执行完成后返回的位置，栈段）。其他段：代码段（可执行代码，指令）、数据段（全局变量和静态变量，这些变量的声明周期与程序的运行周期相同）、堆段（动态内存分配，堆段的大小是动态的）。
  * 线程上下文
    指线程执行时的环境。包括：**程序计数器（PC）、寄存器（通用寄存器、状态寄存器等）、栈（线程的调用栈）、线程本地存储（TLS）（线程私有的存储空间）**；在多线程程序中，每个线程都有自己的上下文。
  * 进程上下文
    指进程执行时的环境。包括：**程序计数器、寄存器、内存空间（进程的虚拟内存空间）、文件描述符（打开的文件和设备）、环境变量（进程的环境变量）**；在操作系统中，每个进程都有自己的上下文。
  * 网络上下文
    指网络通信中的环境。包括：**IP地址（本地和远程IP地址）、端口号（本地和远程端口号）、协议（使用的网络协议，如TCP、UDP）、套接字**
  * 数据库上下文
    指数据库操作的环境。包括：连接信息、事务状态、查询上下文（当前执行的SQL查询及其参数）、会话信息
  * Web 上下文
    指Web应用程序的环境。包括：请求信息（HTTP请求的详细信息，如请求方法、URL、头信息等）、响应信息、会话信息、上下文对象（如HttpContext对象，包含请求和响应的所有信息）

### 线程概念与多线程模型
![](../img/02-进程管理/250602-151942.png)
![](../img/02-进程管理/250602-162048.png)

1. 什么是线程、引入线程的原因
  ![](../img/02-进程管理/250602-153051.png)
  ![](../img/02-进程管理/250602-153840.png)
  - 传统的进程是程序执行流的最小单位；
  - 进程可能有多任务处理的需求，而进程只能串行地执行一系列程序。为此，引入了线程，来增加并发度；
  - 线程是 `CPU` 的基本执行单元，即程序执行流的最小单位；
  - 一个进程可以包含多个线程，多个线程可以使用相同的程序，也可以使用不同的程序。它们都是调度的最小单位，即通过线程实现并发；
2. 引入线程后带来的变化
   ![](../img/02-进程管理/250602-154348.png)
  - 引入线程后，线程成为了程序执行流的最小单位，但资源分配的单位还是进程；
  - **线程的引入提高了系统的并发度**；
  - 同一进程间的线程切换系统开销小；
3. 线程的属性
  ![](../img/02-进程管理/250602-154659.png)
  - 每个线程都有线程 ID、线程控制块 TCB；
  - 线程也有就绪、阻塞和运行三种状态；
  - 同一进程的不同线程间共享进程的资源。它们共享内存地址空间，因而同一进程中的线程通信甚至无需系统干预；
  - 不同进程间的线程切换，会引起进程切换；相同进程间的线程切换，不会引起线程切换；
4. 线程的实现方式和多线程模型
  ![](../img/02-进程管理/250602-155049.png)
  - 用户级线程实现
  ![](../img/02-进程管理/250602-155552.png)
  ![](../img/02-进程管理/250602-155730.png)
     - 线程管理工作都由应用程序负责，包括线程切换；
     - 线程切换在用户态下完成；
     - 在操作系统角度上，看不到用户级线程的存在。调度的最小单位依然是进程；
     - 优点：用户级线程不涉及进程状态的转换，开销小，效率高；
     - 缺点：当其中一个线程被阻塞时，整个进程都会被阻塞，并发程度不高；同时，多个线程也不能在多核处理器上并行运行；
 - 内核级线程实现
  ![](../img/02-进程管理/250602-160703.png)
     - 线程管理工作由操作系统内核完成；
     - 线程切换需要进程状态的转变，在内核态下完成；
     - 操作系统会为每个内核级线程建立相应的 `TCB, Thread Control Block`（线程控制块），通过 `TCB` 对线程进程管理。
     - 在操作系统角度上，能够意识到线程的存在，调度的最小单位是线程；
     - 优点：当一个线程被阻塞后，别的线程不受影响，并发能力强；多线程可以在多核处理机上并行执行；
     - 缺点：一个用户进程会占用多个内核线程，线程切换由操作系统内核完成，需要切换到核心态。因此，线程管理成本高，开销大；
 - 多线程模型

### 处理机调度的概念及层次
![](../img/02-进程管理/250602-163037.png)
![](../img/02-进程管理/250602-164951.png)
- 调度即按照某种规则来决定处理任务的顺序；
- 作业调度：从外存中选择任务并存入内存中，同时建立进程的 `PCB`；进程调度：从内存中选择进程上处理机运行；内存调度：从外存中读入进程所需的数据，进程的 `PCB` 处于内存中，因此也不会新建 `PCB`；
- 调度的三个层次
  ![](../img/02-进程管理/250602-164846.png)
  - 高级调度：**从外存中**按一定规则挑选一个作业**调入内存，并创建 `PCB`**，每个作业只调入一次，调出一次；**调入时创建 `PCB`，调出时撤销 `PCB`**；
  ![](../img/02-进程管理/250602-163738.png)
  - 低级调度：从就绪队列中选取一个进程，将处理机分配给它（调度单位位于内存中）；
  ![](../img/02-进程管理/250602-163619.png)
  - 中级调度：**进程某些数据从内存调入外存**，`PCB` 仍然保留在内存中。进程转为**挂起状态**，被挂起的进程 `PCB` 会被组织成挂起队列；中级调度发生时，将进程的相关数据从外存读入内存（不创建 `PCB`，`PCB` 已存在于内存中）；
  ![](../img/02-进程管理/250602-163932.png)
- 进程的挂起态与七状态模型
  - 挂起和阻塞的区别：两种状态都是暂时不能获取 `CPU` 的服务，但挂起态是将进程映像调到外存中去了；而阻塞态下进程映像还在内存中；
  ![](../img/02-进程管理/250602-164538.png)

### 作业/进程调度算法
**适用于早期的批处理系统**：
![](../img/02-进程管理/250602-173636.png)
![](../img/02-进程管理/250602-191332.png)

1. 先来先服务——FCFS（First Come First Server）
   ![](../img/02-进程管理/250602-184941.png)
   ![](../img/02-进程管理/250602-184708.png)
   - 非抢占式
   - 不会导致饥饿
   - 主要缺点是：排在长作业（进程）后的短作业需要等待很长时间，导致带权周转时间很大。对短作业用户来说体验不好，即 **`FCFS` 对长作业有利，对短作业不利**；
2. 短作业优先——SJF（Shortest Job First）、短进程优先调度算法——SPF（Shortest Process First）
  ![](../img/02-进程管理/250602-190425.png)
  ![](../img/02-进程管理/250602-185505.png)
  ![](../img/02-进程管理/250602-185945.png)
  ![](../img/02-进程管理/250602-190242.png)
   - `SJF` 和 `SPF` 是非抢占式，`SRTN, Shortest Remaining Time Next`（最短剩余时间优先算法）是抢占式；
   - 会导致饥饿；
   - **作业/进程的运行时间是由用户提供的，并不一定真实，不一定能够做到真正的短作业优先**；
3. 高效应比优先——HRRN（Highest Response Ratio Next）
  ![](../img/02-进程管理/250602-190702.png)
  ![](../img/02-进程管理/250602-191129.png)
  ![](../img/02-进程管理/250602-191026.png)
   - 规则：在每次调度时先计算各个作业/进程的响应比，选择响应比最高的作业/进程为其服务。响应比=（等待时间+要求服务时间）/ 要求服务时间，响应比 ≥ 1；
   - 非抢占式；
   - 不会导致饥饿；

**适用于交互式系统**：常用于分时、实时操作系统，更注重“响应时间”。
![](../img/02-进程管理/250602-193519.png)
![](../img/02-进程管理/250602-202503.png)

1. 时间片轮转调度算法（`RR, Round-Robin`）
   ![](../img/02-进程管理/250602-195409.png)
   ![](../img/02-进程管理/250602-195053.png)
   ...
   ![](../img/02-进程管理/250602-195226.png)
   ![](../img/02-进程管理/250602-194721.png)
   - 只用于进程调度
   - 需要选择适中的时间片，过大（退化为先来先服务，增大进程的响应时间）和过小（过多的时间浪费在进程调度和切换上）都存在问题；一般来说，设计时间片时要让切换进程的开销占比不超过 1%；
2. 优先级调度算法
   ![](../img/02-进程管理/250602-201048.png)
   ![](../img/02-进程管理/250602-200249.png)
   ![](../img/02-进程管理/250602-200500.png)
   ![](../img/02-进程管理/250602-200859.png)
   - 通常，操作系统更偏好 `I/O` 繁忙型进程；
3. 多级反馈队列调度算法
  ![](../img/02-进程管理/250602-201146.png)
  ![](../img/02-进程管理/250602-202225.png)
  ![](../img/02-进程管理/250602-201647.png)
  - 新进程达到时，被放入优先级最高的队列队尾；
  - 若用完时间片进程还未结束，则进程进入下一级队列队尾；如果此时已经在最下级的队列，则重新放回最下级队列队尾；
  - 只有高优先级的队列为空时，才会为低优先级的队头分配时间片；
  - 当高优先级的进程达到时，当前的低优先级进程被抢占，它被放回原队列队尾；
  ![](../img/02-进程管理/250602-203243.png)
  - 系统设置多个就绪队列，它们的优先级各不相同。每次调度发生时，选中一个就绪队列，并应用相应的调度算法进行进程调度；而就绪队列的选择可以根据优先级和时间片划分等方式；

### 多处理机调度
![](../img/02-进程管理/250602-203355.png)
![](../img/02-进程管理/250602-205606.png)
1. 与单处理机相比，需要面临的新问题：
   - 除通过调度算法选择哪个进程上处理机上运行外，还需要选择该进程上哪个处理机上运行
  ![](../img/02-进程管理/250602-203615.png)
     - 两个新的调度目标：负载均衡和处理机亲和性
      ![](../img/02-进程管理/250602-203917.png)
      - 其中，处理机亲和性主要是为了充分利用 `CPU` 中的 `Cache`，从而减少对内存的访问；当某进程在某 `CPU` 上运行时，其进程数据保存在 `Cache` 中，因此当下一次该进程再度被调度上处理运行时，应该更多地考虑到该处理机上运行；
2. 方案 1：公共就绪队列
   ![](../img/02-进程管理/250602-204730.png)
   - 天然实现了负载均衡，因为当处理机空闲就会进行调度；
3. 方案 2：私有就绪队列
   ![](../img/02-进程管理/250602-205016.png)
   ![](../img/02-进程管理/250602-205140.png)
   ![](../img/02-进程管理/250602-205256.png)
   - 天然实现了处理机亲和；但是还可以通过系统调用，指定进程只在某一个处理机上运行；
