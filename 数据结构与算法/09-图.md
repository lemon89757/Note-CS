## 基本概念
- 图是一种**非线性**数据结构，*由顶点和边组成*。可以将图 $G$ 抽象地表示为一组顶点 $V$ 和一组边 $E$的集合。如下表示具有 5 个定点和 7 条边的图。相较于*线性关系（链表）和分治关系（树）*，**网络关系（图）具有的自由度更高**，因而更为复杂。
$$
\begin{align}
    V &= \{1, 2, 3, 4, 5\} \\
    E &= \{(1, 2), (1,3), (1,5), (2,3), (2,4), (2,5), (4,5)\} \\
    G &= \{V, E\}
\end{align} 
$$

## 常见类型与术语
- 根据边是否具有方向，可以分为**有向图和无向图**。（如：无向图-微信中的好友关系，有向图-微博上的关注与被关注关系）
- 根据所有顶点是否连通，可以分为**连通图和非连通图**。对于连通图，从某个顶点出发，可以到达其中任意顶点；对于非连通图，从某个顶点出发，至少有一个顶点无法到达。
- 可以为边添加权重变量，从而得到**有权图**。
- 强连通图和强连通分量：**在有向图中**，任意两个节点都是可以相互到达的；在有向图中极大强连通子图称之为该图的强连通分量。
- 连通分量：**在无向图中**的极大连通子图称之为该图的一个连通分量。
- 相关术语：
  1. 邻接：两顶点之间存在边相连时 
  2. 路径：从顶点 `A` 到顶点 `B` 经过的**边**构成的序列被称为从 `A` 到 `B`的路径
  3. **度**：一个顶点拥有的边数。对于有向图，**入度**：表示有多少条边指向该顶点；**出度**：表示有多少条边从该顶点指出。

## 图的表示
**常用的表示方式包括“邻接矩阵”和“邻接表”**

### 邻接矩阵
记图的顶点数量为 $n$，邻接矩阵使用一个 $n * n$ 大小的矩阵来表示图。**每一行/列代表一个顶点，矩阵元素代表边，用 1 或 0 表示两个顶点之间是否存在边**，也可以用权重填充矩阵元素。
- 在简单图中，顶点不能与自身相连，此时邻接矩阵主对角线元素没有意义
- 对于无向图，两个方向的边等价，此时邻接矩阵关于主对角线对称
- 将邻接矩阵的元素从 1 和 0 替换为权重，则可表示有权图

使用邻接矩阵表示图时，可以直接访问矩阵元素以获取边，因此增删查改操作的效率很高，时间复杂度均为 $O(1)$。然而，矩阵的空间复杂度为 $O(n^2)$，内存占用较多。

- 优点：
  1. 表达方式简单，易于理解
  2. 检查任意两个顶点是否存在边的操作非常块
  3. **适合稠密图**，在边数接近顶点数平方的图中，邻接矩阵是一种空间效率较高的表示方法
- 缺点：
  1. **不适合稀疏图**，会导致申请过大的二维数组造成空间浪费，且遍历边时需要遍历整个 $n * n$ 矩阵，造成时间浪费。

### 邻接表
邻接表*使用 $n$ 个链表*来表示图，链表节点表示顶点（可以使用数组 + 链表来表达边的连接情况。数组中每个元素对应链表节点的顶点，即图中的顶点）。第 $i$ 个链表对应顶点 $i$，其中存储了该顶点的所有邻接顶点。
邻接表仅存储实际存在的边，而边的总数通常远小于 $n^2$，因此它更加节省空间。然而，在邻接表中需要通过遍历链表来查找边，因此时间效率不如邻接矩阵。
邻接表结构与哈希表中的“链式地址”非常相似，因此可以采用类似的方法来优化效率。比如**当链表较长时，可以将链表转化为 AVL 树或者红黑树，从而将时间效率从 O(n) 优化至 O(logn)**；还可以把链表转换为**哈希表**，从而将时间复杂度降至 $O(1)$

- 优点
  1. 对于稀疏图的存储，只需要存储边，空间利用率高
  2. 遍历顶点连接情况相对容易
- 缺点
  1. 检查任意两个顶点间是否存在边，效率相对较低，需要 $O(M)$ 时间。$M$ 表示某顶点连接其他顶点的数量。
  2. 实现相对复杂，不易理解。

### 常见应用
* 社交网络      用户    好友关系            潜在好友推荐
* 地铁线路      站点    站点间的连通性      最短线路推荐
* 太阳系        星体    星体间的万有引力    行星轨道计算

## 图的基础操作
图的基础操作可分为*对“边”的操作和对“顶点”的操作*。在“邻接矩阵”和“邻接表”两种表示方法下，实现有所不同。

### 基于邻接矩阵的实现
给定一个顶点总数为 $n$ 的无向图：
* 添加或删除边：直接在邻接矩阵中修改指定的边即可，使用 $O(1)$ 时间。无向图需要同时更新两个方向的边。
* 添加顶点：在邻接矩阵的尾部添加一行一列，并全部填 0 即可，使用 $O(n)$ 时间。
* 删除顶点：在邻接矩阵中删除一行一列。当删除首行首列时达到最差情况，需要将 $(n - 1)^2$ 个元素“向左上移动”，从而使用 $O(n^2)$ 时间
* 初始化：传入 $n$ 个节点，初始化长度为 $n$ 的顶点列表，使用 $O(n)$ 时间；初始化 $n * n$ 大小的邻接矩阵，使用 $O(n^2)$ 时间。
```C++
/* 基于邻接矩阵实现的无向图类 */
class GraphAdjMat{
    vector<int> vertices;           // 顶点列表，元素代表“顶点值”，索引代表“顶点索引”
    vector<vector<int>> adjMat;     // 邻接矩阵，行列索引对应“顶点索引”
public:
    GraphAdjMat(const vector<int> &vertices, const vector<vector<int>> &edges){
        // 添加顶点
        for(int val : vertices){
            addVertex(val);
        }
        // 添加边
        for(cosnt vector<int> &edge : edges){
            addEdge(edge[0], edge[1]);
        }
    }

    /* 获取顶点数量 */
    int size() const{
        return vertices.size();
    }

    /* 添加顶点 */
    void addVertex(int val){
        int n = size();
        vertices.push_back(val);
        /* 在邻接矩阵中添加一行 */
        adjMat.emplace_back(vector<int>(n, 0));
        /* 在邻接矩阵中添加一列 */
        for(vector<int> &row : adjMat){
            row.push_back(0);
        }
    }

    /* 删除顶点 */
    void removeVertex(int index){
        if(index >= size()){
            // 此处 index 应该需要或上 < 0 的条件?
            throw out_of_range("顶点不存在");
        }
        // 在顶点列表中移除索引 index 的顶点
        verties.erase(vertices.begin() + index);
        // 在邻接矩阵中删除索引 index 行 
        adjMat.erase(adjMat.begin() + index);
        // 在邻接矩阵中删除索引 index 的列
        for(vector<int> &row : adjMat){
            row.erase(row.begin() + index);
        }
    }

    /* 添加边 
     * 参数 i，j 对应 verties 元素索引
    */
    void addEdge(int i , int j){
        if(i < 0 || j < 0 || i >= size() || j >= size() || i == j){
            throw out_of_range("顶点不存在");
        }
        // 无向图中邻接矩阵关于主对角线对称
        adjMat[i][j] = 1;
        adjMat[j][i] = 1;
    }

    /* 删除边 */
    void removeEdge(int i, int j){
        if(i < 0 || j < 0 || i >= size() || j >= size() || i == j){
            throw out_of_range("顶点不存在");
        }
        // 无向图中邻接矩阵关于主对角线对称
        adjMat[i][j] = 0;
        adjMat[j][i] = 0;
    }

    /* 打印邻接矩阵 */
    void print(){
        cout << "顶点列表 = ";
        printVector(verties);
        cout << "邻接矩阵 = ";
        printMatrix(adjMat);
    }
}
```

### 基于邻接表的实现
给定一个顶点总数为 $n$、边总数为 $m$ 的无向图：
* 添加边：在顶点对应链表的末尾添加边即可，使用 `O(1)`时间。无向图，需要同时添加两个方向的边。
* 删除边：在顶点对应链表中查找并删除指定边，使用`O(m)`时间。无向图，需要同时删除两个方向的边。
* 添加顶点：在邻接表中添加一个表，并将新增顶点作为链表头节点，使用 `O(1)` 时间
* 删除顶点：需遍历整个邻接表，删除包含指定顶点的所有边，使用 `O(n + m)`（todo：为什么不是 `O(n * m)` ？）
* 初始化：在邻接表中创建 $n$ 个顶点和 $2m$ 条边，使用 `O(n + m)` 时间。（todo：时间复杂度?）
```C++
/* 基于邻接表实现的无向图类 */
class GraphAdjList{
public:
    // 邻接表，key：顶点；value：该顶点的所有邻接顶点
    unordered_map<Vertex *, vector<Vertex *>> adjList;

    /* 在 vector 中删除指定节点 */
    void remove(vector<Vertex *> &vec, Vertex *vet){
        for(int i = 0; i < vec.size(); i++){
            if(vec[i] == vet){
                vec.erase(vec.begin() + i);
                break;
            }
        }
    }

    /* 构造方法 */
    GraphAdjList(const vector<vector<Vertex *>> &edges){
        for(const vector<Vertex *> &edge : edges){
            // 添加所有顶点和边
            addVertex(edge[0]);
            addVertex(edge[1]);
            addEdge(edge[0], edge[1]);
        }
    }

    /* 获取顶点数量 */
    int size(){
        return adjList.size();
    }

    /* 添加边 */
    void addEdge(Vertex *vet1, Vertex *vet2){
        if(!adjList.count(vet1) || !adjList.count(vet2) || vet1 == vet2)
            throw invalid_argument("不存在顶点");
        // 添加边 vet1 - vet2
        adjList[vet1].push_back(vet2);
        adjList[vet2].push_back(vet1);
    }

    /* 删除边 */
    void removeEdge(Vertex *vet1, Vertex *vet2){
        if(!adjList.count(vet1) || !adjList.count(vet2) || vet1 == vet2)
            throw invalid_argument("不存在顶点");
        // 删除边 vet1 - vet2
        remove(adjList[vet1], vet2);
        remove(adjList[vet2], vet1);
    }

    /* 添加顶点 */
    void addVertex(Vertex *vet){
        if(adjList.count(vet)){
            return;
        }
        // 在邻接表中添加一个新链表
        adjList[vet] = vector<Vertex *>();
    }

    /* 删除顶点 */
    void removeVertex(Vertex *vet){
        if(!adjList.count(vet))
            throw invalid_argument("不存在顶点");
        // 在邻接表中删除顶点 vet 对应的链表
        adjList.erase(vet);
        // 遍历其他顶点的链表，删除所有包含 vet 的边
        for(auto &adj : adjList){
            remove(adj.second, vet);
        }
    }

    /* 打印邻接表 */
    void print(){
        cout << "邻接表 = " << endl;
        for(auto &adj : adjList){
            const auto &key = adj.first;
            const auto &vec = adj.second;
            cout << key->val << ":";
            printVector(vetsToVals(vec));
        }
    }
}
```
* 为了方便添加与删除顶点，以及简化代码，**使用列表（动态数组）来替代链表**
* **使用哈希表来存储邻接表**，`key` 为顶点实例，`value` 为该顶点的邻接顶点列表（链表）。
* 在邻接表中使用 `Vertex` 类来表示顶点，原因是：如果与邻接矩阵一样，用列表索引来区分不同顶点，那么假设要删除索引为 $i$ 的顶点，则需要遍历整个邻接表，将所有大于 $i$ 的索引全部减 1，效率很低。而**如果每个顶点都是唯一的 `Vertex` 实例，删除某一顶点之后就无须改动其他顶点了**。（todo：？）

### 效率对比
设图中共有 $n$ 个顶点和 $m$ 条边（todo：？）：
|    | 邻接矩阵   | 邻接表（链表）   |  邻接表（哈希表）   |
|:--------:|:--------:|:--------:|:--------:|
| 判断是否邻接 | $O(1)$ | $O(m)$ | $O(1)$ |
| 添加边 | $O(1)$ | $O(1)$ | $O(1)$ |
| 删除边 | $O(1)$ | $O(m)$ | $O(1)$ |
| 添加顶点 | $O(n)$ | $O(1)$ | $O(1)$ |
| 删除顶点 | $O(n^2)$ | $O(n + m)$ | $O(n)$ |
| 内存空间占用 | $O(n^2)$ | $O(n + m)$ | $O(n + m)$ |

似乎邻接表（哈希表）的时间效率与空间效率最优。但实际上，**在邻接矩阵中操作边的效率更高**，只需一次数组访问或赋值操作即可。综合来看，邻接矩阵体现了“以空间换时间”的原则，而邻接表体现了“以时间换空间”的原则。

## 图的遍历
### 深度优先遍历`DFS`
```C++
void dfs(GraphAdjList &graph, unordered_map<Vertex *> &visited, vetor<Vertex *> &res, Vertex *vet){
    res.push_back(vet);
    visited.emplace(vet);
    for(Vertex *adjVet : graph.adjList[vet]){
        if(visited.count[adjVet]) continue;
        dfs(graph, visited, res, adjVet);
    }
}

vector<Vertex *> graphDFS(GraphAdjList &graph, Vertex *startVet){
    vector<Vertex *> res;
    unordered_map<Vertex *> visited;
    dfs(graph, visited, res, startVet);
    return res;
}
```
* 深度优先遍历序列的顺序也不是唯一的
* 时间复杂度：$O(|V| + |E|)$
* 空间复杂度：$O(|V|)$

### 广度优先遍历`BFS`
```C++
/* 广度优先遍历 */
vector<Vertex *> graphBFS(GraphAdjList &graph, Vertex *startVet){
    vertor<Vertex *> res;
    unordered_map<Vertex *> visited = {startVet};
    queue<Vertex *> que;
    // 这里是不是还应该先判断 startVet 是否为空
    que.push(startVet);
    while(!que.empty()){
        Vertex *vet = que.front();
        que.pop();
        res.push_back(vet);
        for(auto adjVet : graph.adjList[vet]){
            if(visited.count(adjVet)) continue;
            que.push(adjVet);
            visited.emplace(adjVet);
        }
    }
    return res;
}
```
* 为了防止重复遍历顶点（因为顶点 `A` 可能作为 `root` 的邻接点，也能作为 `root` 的邻接点的邻接点；同时在无向图中 `A` 是 `root` 的邻接点，`root` 也是 `A` 的邻接点），需要借助一个哈希集合 `visited` 来记录哪些节点被访问（也可以使用其他结构来作记录）。
* 哈希集合可以看作一个只存储 `key` 而不存储 `value` 的哈希表，它可以在 $O(1)$ 时间复杂度下进行 `key` 的增删查改操作。根据 `key` 的唯一性，哈希集合通常用于数据去重等场景。
* 广度优先遍历的序列不唯一，只要求按“由近及远”的顺序遍历，而**多个相同距离的顶点的遍历顺序允许被任意打乱**。
* 时间复杂度：$O(|V| + |E|)$。所有顶点都会入队并出队一次，使用 $O(|V|)$ 时间；在遍历邻接顶点的过程中，由于是无向图，因此所有的边都会被访问 2 次，使用 $O(2|E|)$ 时间。总体使用 $O(|V| + |E|)$ 时间。
* 空间复杂度：$O(|V|)$。列表 `res`，哈希集合 `visited`，队列 `que` 中顶点数量最多为 $O(|V|)$。

## 并查集
> [代码随想录](https://www.programmercarl.com/kamacoder/%E5%9B%BE%E8%AE%BA%E5%B9%B6%E6%9F%A5%E9%9B%86%E7%90%86%E8%AE%BA%E5%9F%BA%E7%A1%80.html#%E8%83%8C%E6%99%AF)

- 并查集解决的问题：
    并查集常用来解决连通性问题，主要功能是：
    - 判断两个元素在不在同一个集合里；
    - 将两个元素添加到一个集合里；
- 主要思路：
    - 通过创建节点数组，其中数组下标表示节点，值表示该节点的根；
    - 当两个节点具有相同的根时表示两节点在一个集合里；
    - 节点根的表示可以通过第一次查找根时进行优化，直接将根赋值给数组的对应元素；因此判断两个节点是否在同一个集合时，时间复杂度在 `O(logn)` 和 `O(1)` 之间，当查找次数增加时时间复杂度越靠近 `O(1)`。其中 `logn` 是第一次查找进行优化时的节点到根的高度，`n` 表示元素个数；
- 代码框架：
    ```C++
    vector<int> parent(n, 0);

    void init(){
        for(int i = 0; i < parent.size(); i++){
            // 初始化，将每个节点的根节点初始化为自身
            parent[i] = i;
        }
    }

    void find(int a){
        if(a == parent[a]) return;
        else return parent[a] = find(parent[a]);        // 在查找节点的根时进行优化，直接将根的值赋给对应数组元素
    }

    /* 判断两个元素是否在同一个集合里 */
    bool isSmae(int a, int b){
        a = find(a);
        b = find(b);
        return a == b;
    }

    /* 将两个节点放入同一个集合中 */
    void join(int a, int b){
        a = find(a);
        b = find(b);
        // 根相同时，表示已在同一个集合中，直接返回
        if(a == b) return;
        // 将 a 的根作为 b 的根
        parent[b] = a;          // 其实这里是将 b 的根（原来的根）的根赋值为 a 的根
        // 因此不能直接在省略查找 a, b 的根的步骤，直接在 a 与 b 不相等时，以 a 作为 b 的根
    }
    ```

## 最小生成树
最小生成树是指一个连通图的最小权重生成树。在图论中，**生成树是包含图中所有顶点的一个无环子图**，而最小生成树则是在所有生成树中边的权重之和最小的那颗。应用：网络设计、电路布线等。**图中有 `n` 个节点，那么一定可以用 `n - 1` 条边将所有节点连接到一起**。

> [代码随想录](https://www.programmercarl.com/kamacoder/0053.%E5%AF%BB%E5%AE%9D-prim.html#%E8%A7%A3%E9%A2%98%E6%80%9D%E8%B7%AF)
- `prim` 算法
  - 从节点的角度，采用贪心策略，每次寻找距离最小生成树最近的节点（即该节点与生成树中某一结点的权重在所有未在生成树中的节点中是最小的）；
  - 将选择的节点加入到生成树中；
  - 更新非生成树节点到生成树的最小距离；

  在上述表述中，距离即权重，通过维护一个一维数组来表示每个节点与生成树的最小距离，**一维数组的初始值可以选择权值允许最大值 + 1**；通过维护一个一维数组来表示节点是否已加入生成树，因此**在节点选择和距离值更新时只需要考虑未加入到树中的节点即可**；

  - 若结果只需要对最小权值做输出，则只需计算记录最小距离数组的元素累加和；

4. 方法 1：[leetcode官方题解](https://leetcode.cn/problems/reconstruct-itinerary/solutions/389885/zhong-xin-an-pai-xing-cheng-by-leetcode-solution/)。
几个概念：
   - 欧拉通路：通过图中所有边恰好一次且行遍所有顶点的通路称为欧拉通路
   - 欧拉回路：通过图中所有边恰好一次且行遍所有顶点的回路称为欧拉回路
   - 具有欧拉回路的无向图称为欧拉图
   - 具有欧拉通路但不具有欧拉回路的无向图称为半欧拉图

**这种“一笔画”问题与欧拉图或者半欧拉图有着紧密的联系**，题中保证了至少存在一种合理的路径，也就告诉我们这是一张欧拉图或者半欧拉图。`Hierholzer` 算法用于在连通图中寻找欧拉路径，流程为：
   1. 从起点出发，进行深度优先搜索；
   2. 每次沿着某条边从某个顶点移动到另外一个顶点的时候，**都需要删除这条边**（避免死循环）
   3. 如果没有可移动的路径，则将所在节点加入到栈中，并返回

如果顺序地考虑该问题，也许很难解决该问题，因为无法判断当前节点的哪一个分支是 “死胡同” 分支；不妨倒过来思考，注意到只有那个入度与出度差为 1 的节点会导致死胡同。**而该节点必然是最后一个（才能）遍历到的节点**。可以改变入栈规则，**只有当遍历完一个节点所连的所有节点后，才将该节点入栈**。对于当前节点而言，**从它的每一个非“死胡同”分支出发进行深度优先搜索，都将会搜回到当前节点。而从它的“死胡同”分支出发进行深度优先搜索将不会搜回到当前节点。也就是说当前节点的死胡同分支将会优先于其他非“死胡同”分支入栈**。这样就能保证可以“一笔画”地走完所有边，最终的栈中*逆序*地保存了“一笔画”的结果。上述内容是从结果层面分析的：“当前节点的死胡同分支将会优先于其他非“死胡同”分支入栈”，这是完成“一笔画”的所需条件。原因是：1. 遍历过的边会被删除，因此不会导致无限递归；2. 题中保证至少有一条合理路径；3. 遍历当前的所有连接到的顶点或才将当前节点入栈，这会出现导致（不妨假设当前节点可以选择两条路径，其中一个是“死胡同”）：先深度递归“死胡同”方向的节点，“死胡同”方向的最后一个节点先入栈；先深度递归另外一个方向的节点，由于还能从该方向返回到当前节点、遍历过的边被删除、需要遍历完当前节点的所有连接点才能将当前节点放入栈中等条件，当回到出发的当前节点处时，继续深度遍历（往“死胡同”方向），因此最终还是“死胡同”方向上的终点先入栈。
```C++
class Solution{
public:
    // 使用哈希表记录每个顶点的连接点情况，避免反复遍历原始链表寻找当前顶点的下一个连接点；连接点通过优点队列排序，从而实现路径的最小字典序
    unordered_map<string, priority_queue<string, vector<string>, std::greater<string>>> vec;
    vector<string> stk;

    void dfs(const string& cur){
        while(vec.count(cur) && vec[cur].size() > 0){
            string tmp = vec[cur].top();
            vec[cur].pop();
            // 将 tmp（临时变量） 通过 std::move 转换为右值引用
            // 可以增加临时变量的生命周期，同时实现资源的高效转移
            dfs(move(tmp));
        }
        stk.emplace_back(cur);
    }

    vector<string> findItinerary(vector<vector<string>> &tickets){
        stk.clear();
        // 另一种遍历方式
        for(auto &it : tickets){
            // 往堆中添加元素
            vec[it[0]].emplace(it[1]);
        }
        dfs("JFK");
        // reverse 返回类型是 void；不能直接 return reverse(stk.begin(), stk.end());
        reverse(stk.begin(), stk.end());
        return stk;
    }
};
```

```C++
            return route;
```

```C++
private:
    // 同样使用哈希表来记录顶点与连接点的关系；在连接点中同样也是一个哈希表，用来保存顶点和允许遍历顶点的次数，同时 map 是有序的，便于实现最小字典序
    unordered_map<string, map<string, int>> targets;

    // 具有返回值，找到满足题意条件的结果即返回。问题的解只有一个
    bool backtracking(int ticketNum, vector<string> &result){
        // 当结果中的元素比机票数多一时表示找到结果，即返回
        if(result.size() == ticketNum + 1) return true;

        // 遍历当前顶点的连接点；
        // 由于采用 map 所以满足了最小字典序的要求
        // 同时就算先遍历到“死胡同”，由于不满足结束条件而不会结束查找
        for(pair<const string, int> &target : targets[result[result.size() - 1]]){
            // 判断是否还能遍历此顶点
            if(target.second > 0){
                result.emplace_back(target.first);
                target.second--;
                // 如果找到了结果，即为满足题意的最小字典序路径，无需再递归回溯查找
                if(backtracking(ticketNum, result)) return true;
                target.second++;
                result.pop_back();
            }
        }
        return false;
    }

public:
    vector<string> findItinerary(vector<vector<string>> &tickets){
        targets.clear();
        vector<string> res;
        for(const vector<string> &vec : tickets){
            targets[vec[0]][vec[1]]++;
        }
        res.emplace_back("JFK");
        backtracking(tickets.size(), res);
        return res;
    }
};
```

```C++
class Solution{
private:
    int directions[4][2] = {1, 0, -1, 0, 0, 1, 0, -1};

public:
    int orangesRotting(vector<vector<int>>& grid){
        int time = 0;
        int size;
        int nextX, nextY;
        queue<pair<int, int>> que;

        for(int i = 0; i< grid.size(); i++){
            for(int j = 0; j < grid[0].size(); j++){
                if(grid[i][j] == 2) que.push({i, j});
            }
        }

        while(!que.empty()){
            size = que.size();
            for(int i = 0; i < size; i++){
                pair<int, int> cur = que.front();
                que.pop();
                for(int i = 0; i < 4; i++){
                    nextX = cur.first + direction[i][0];
                    nextY = cur.second + direction[i][1];
                    if(nextX < 0 || nextX >= grid.size() || nextY < 0 || nextY >= grid[0].size()) continue;
                    if(grid[nextX][nextY] == 1){
                        grid[nextX][nextY] = 2;
                        que.push({nextX, nextY});
                    }
                }
            }
            time++;
        }

        for(int i = 0; i < grid.size(); i++){
            for(int j = 0; j < grid[0].size(); j++){
                if(grid[i][j] == 1) return -1;
            }
        }

        // 最后 time 可能多加了 1；另外也可能不存在腐烂扩散的现象
        return time == 0 ? time : time - 1;
    }
```

6. 关于**拓扑排序**：
   - 给定一个包含 n 个节点的有向图 G，给出它的节点编号的一种排列，如果满足：*对于图 G 中的任意一条有向边（u,v），u 在排列中都出现在 v 的前面*，那么称该排列是图 G 的拓扑排序。根据上述的定义，可以得出两个结论：
   - **如果图 G 中存在环（即图 G 不是有向无环图），那么图 G 不存在拓扑排序**。
   - **如果图 G 是有向无环图，那么它的拓扑排序可能不止一种**。
   - 概括来说，给出一个有向图，把这个有向图转换成线性的排序，就叫拓扑排序。拓扑排序指的是一种解决问题的大体思路，而具体算法，可能是广搜也可能是深搜
   - **拓扑排序也是图论中判断有向无环图的常用方法**
   - BFS 思路：
     1. 找到入度为 0 的节点，加入结果集
     2. 将该节点从图中移除
循环以上两步，直到所有节点都在图中被移除。结果集的顺序，就是拓扑排序顺序（结果集里顺序可能不唯一）。**如果最终结果集中的元素个数不等于图中节点个数，就可以认定图中一定有有向环**，这也是拓扑排序判断有向环的方法。对于上述第 2 点，本质上是将以该节点作为出发点所连接的节点的入度减一就可以了，这样便可以根据更新后的入度情况找到下一个入度为 0 的节点，而不用真在图中把这个节点删掉。对于 BFS 的终止条件，即结果集为空时 BFS 终止，因此存在 BFS 中元素个数与图中节点个数不符的情况，此时图中存在有向环。
   - 对于 207.课程表问题，因为在课程之间存在依赖关系，需要上完一门课程 A 后才能上另外一门课程 B，即 B 依赖 A。因此，可以将课程之间的这种关系用图的结构来表示。采用 BFS 时代码如下：
    ```C++
    class Soulution{
    private:
        // 记录从节点出发的边
        vector<vector<int>> edges;
        // 记录节点的入度
        vector<int> indeg;
    public:
        bool canFinish(int numCourses, vector<vector<int>>& prerequisites){
            // 邻接表表示边
            edges.resize(numCourses);
            indeg.resize(numCourses);
            for(const auto& info : prerequisites){
                // info[0] 依赖于 info[1]，即存在从节点 info[1] 指向 info[0] 的边
                edges[info[1]].push_back(info[0]);
                // 更新对应节点的入度
                ++indeg[info[0]];
            }

            // 通过队列保存入度为 0 的节点
            queue<int> que;
            for(int i = 0; i < numCourses; i++){
                if(indeg[i] == 0) que.push(i);
            }

            int visited = 0;
            while(!que.empty()){
                ++visited;
                int cur = que.front();
                que.pop();
                // 遍历入度为 0 的节点的相邻节点，更新相邻节点的入度
                for(int next : edges[cur]){
                    --indeg[next];
                    if(indeg[next] == 0) que.push(next);
                }
            }

            return visited == numCourses;
        }
    }
    ```

   - DFS思路：
        1. 可以将深度优先搜索的流程与拓扑排序的求解联系起来，**用一个栈来存储所有已经搜索完成的节点**。*对于一个节点 u，如果它的所有相邻节点都已经搜索完成，那么在搜索回溯到 u 的时候，u 本身也会变成一个已经搜索完成的节点。这里的“相邻节点”指的是从 u 出发，通过一条有向边可以到达的所有节点*。
        2. 假设当前搜索到了节点 u，如果它的所有相邻节点都已经搜索完成，那么这些节点都已经在栈中了，此时就可以把 u 入栈。可以发现，如果从栈顶往栈底的顺序看，由于 u 处于栈顶位置，那么 u 出现在所有 u 的相邻节点的前面。因此对于 u 这个节点而言，它是满足拓扑排序要求的。
        3. 这样一来，对图进行一遍深度优先搜索。当每个节点进行回溯的时候，把该节点放入栈中。最终从栈顶到栈底的序列就是一种拓扑排序。
        4. 对于图中的任意一个节点，它**在搜索的过程中有三种状态**：
           1. 未搜索
           2. 搜索中：搜索过该节点，但还没有回溯到该节点，即该节点还没有入栈，还有相邻的节点没有搜索完成
           3. 已完成：搜索过并且回溯过该节点，即该节点已经入栈，并且所有该节点的相邻节点都出现在栈的更底部的位置，满足拓扑排序的要求。
        5. 深度优先搜索的拓扑排序的算法流程：
           1. 在每一轮的搜索开始时，任取一个 未搜索 的节点开始进行深度优先搜索；
           2. 将当前所搜节点 u 标记为 搜索中，遍历该节点的每一个相邻节点 v；
           3. 如果 v 为 未搜索，那么开始搜索 v，待搜索完成回溯到 u；**如果 v 为搜索中，那么就找到了图中的一个环，因此不存在拓扑排序**；如果 v 为 已完成，那么说明 v 已经在栈中了，而 u 还不在栈中，因此 u 无论何时入栈都不会影响到（u，v）之前的拓扑关系，以及不用进行任何操作
           4. 当 u 的所有相邻节点都为 已完成 时，将 u 放入栈中，并将其标记为 已完成。
           5. 在整个深度优先搜索的过程结束后，如果没有找到图中的环，那么栈中存储这所有的 n 个节点，从栈顶到栈底的顺序即为一种拓扑排序。
    ```C++
    class Solution{
    private:
        vector<vector<int>> edges;
        // 标记节点的三种状态：0-未搜索；1-搜索中；2-完成搜索
        vector<int> visited;
        bool valid = true;
    public:
        void dfs(int u){
            visited[u] = 1;
            for(int v : edges[u]){
                if(visited[v] == 0){
                    dfs(v);
                    if(!valid) return;
                }else if(visited[v] == 1){
                    valid = false;
                    return;
                }
            }
            visited[u] = 2;
        }

        bool canFinish(int numCourses, vector<vector<int>>& prerequisites){
            edges.resize(numCourses);
            visited.resize(numCourses);
            for(const auto& info : prerequisites){
                edges[info[1]].push_back(info[0]);
            }

            for(int i = 0; i < numCourses && valid; ++i){
                if(!visited[i]){
                    dfs[i];
                }
            }

            return valid;
        }
    }
    ```
   - 事实上，由于**求出一种拓扑排序方法的最优时间复杂度为 `O(n + m)`，其中 `n` 和 `m` 分别是有向图 G 的节点数和边数**。而判断图 G 是否存在拓扑排序，至少也要对其进行一次完整的遍历，时间复杂度也为 `O(n + m)`。因此不可能存在一种仅判断是否存在拓扑排序的方法，它的时间复杂度在渐进意义上严格优于 `O(n + m)`。

    ```C++
        }
    ```

   ```C++
            // index 与 cur 的关系
            int row = (size - 1) - (cur - 1) / size;
            int column;
            if(((cur - 1) / size) % 2){
                column = (size - 1) - (cur - 1) % size;
            }else{
                column = (cur - 1) % size;
            }
            return {row, column};
        }

        int snakesAndLadders(vector<vector<int>>& board) {
            int next;
            int size = board.size();
            int destination = size * size;
            pair<int, int> cur;

            // 标记访问过的位置，避免死循环
            vector<bool> visited(size * size, false);
            // bfs
            queue<pair<int, int>> que;
            que.emplace(1, 0);
            visited[0] = true;
            while(!que.empty()){
                cur = que.front();
                que.pop();

                for(int i = 1; i <= 6; i++){
                    next = cur.first + i;
                    if(next > destination) break;

                    auto nextCoordinate = transfer(next, size);
                    // cout << next << " " << nextCoordinate.first << " " << nextCoordinate.second << endl;
                    if(board[nextCoordinate.first][nextCoordinate.second] != -1){

                    }

                    if(next == destination) return cur.second + 1;

                    if(!visited[next - 1]){
                        que.emplace(next, cur.second + 1);
                        visited[next - 1] = true;
                    }
                }
            }

        }
   ```

   ```C++
                }
            }
   ```
