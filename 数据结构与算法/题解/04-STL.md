`C++` 标准模板库的核心包括以下重要组件：
* 容器(Containers)
各种数据结构，包括向量（vector）、链表（list）、队列（queue）、栈（stack）、集合（set）、映射（map）等。

* 算法(Algorithms)
用于对容器中的元素进行各种操作，包括排序、搜索、复制、移动、变换等。这些算法在使用时**不需要关心容器的具体类型**，只需要指定要操作的范围即可。

* 迭代器(Iterators)
**用于遍历容器中的元素**，允许以统一的方式访问容器中的元素，而**不用关心容器的内部实现细节**。包括：随机访问迭代器、双向迭代器、前向迭代器和输入输出迭代器等。

* 函数对象(Function Objects)
也称**仿函数**，函数对象是**可以像函数一样调用的对象**，可以用于算法中的各种操作。包括：一元函数对象、二元函数对象、谓词等。

* 适配器(Adapters)
**用于将一种容器或迭代器适配成另一种容器或迭代器**，以满足特定的需求。包括：栈适配器（stack adapter）、队列适配器（queue adapter）和优先队列适配器（priority queue adapter）等。

* 空间配置器（内存分配器）

## 容器
用来存储数据的序列，它们提供了**不同的存储方式和访问模式**

### 序列容器
存储元素的**序列**，允许双向遍历（todo：list支持双向遍历？）。
- 特点是：
  1. 线性存储
     - 元素以**线性**序列的方式存储，每个元素都有一个明确的顺序
     - 元素的存储顺序通常与插入顺序一致
  2. 随机访问
     - 除了链表（std::list 和 std::forward_list）外，大多数序列容器支持随机访问，可以通过索引快速访问任意元素
  3. 动态扩展
     - std::vector 和 std::deque 支持动态扩展
     - std::array 的大小是固定的，不能动态扩展
  4. 插入和删除
     - std::vector 和 std::deque 在末尾进行插入和删除操作效率较高
     - std::list 和 std::forward_list（单向链表） 在任意位置进行插入和删除操作效率较高

- 相关容器

### 关联容器
存储**键值对**，每个元素都有一个键（key）和一个值（value），并且**通过键来组织元素**。（todo：set也是存储键值对？）

* `std::set`
1. 集合，不允许重复元素
2. 有序容器，根据元素的值自动排序，通常使用默认的比较函数（如 std::less）
3. 通常使用**红黑树**（一种自平衡二叉搜索树）来实现

* `std::multiset`
1. 多重集合，允许多个重复元素具有相同的键
2. 有序容器，根据元素的值自动排序，通常使用默认的比较函数（如 std::less）
3. 通常使用**红黑树**来实现

* `std::map`
1. 映射，每个键映射到一个值
2. 有序容器，根据键的值自动排序，通常使用默认的比较函数（如 std::less）
3. 通常使用**红黑树**来实现

* `std::multimap`
1. 多重映射，存储了键值对（pair），其中键是唯一的，但值可以重复，允许一个键映射到多个值

### 无序容器
C++11 引入；哈希表，支持快速的查找、插入和删除

* `std::unordered_set`
1. 无序集合
2. 使用**哈希表**来存储元素，元素的顺序是不确定的，取决于哈希函数和哈希表的实现，而不是元素的值

* `std::unordered_multiset`
1. 无序多重集合
2. 使用**哈希表**来存储元素，元素的顺序是不确定的，取决于哈希函数和哈希表的实现，而不是元素的值
   
* `std::unordered_map`
1. 无序映射
2. 使用**哈希表**来存储元素，键的顺序是不确定的，取决于哈希函数和哈希表的实现，而不是键的值
   
* `std::unordered_multimap`
1. 无序多重映射
2. 使用**哈希表**来存储元素，键的顺序是不确定的，取决于哈希函数和哈希表的实现，而不是键的值

## 序列容器

### `vector`

1. `push_back` 和 `emplace_back`：
   - `push_back` 和 `emplace_back` 都用于向 `vector` 中末尾添加元素
   - `push_bcak` 接受一个值（可以是左值或右值）作为参数，并将该值复制或移动到容器末尾；如果传入的值是左值（如普通变量），会调用拷贝构造函数；如果传入的值是右值（如临时对象），会调用移动构造函数； 如果添加的是一个复杂对象（如自定义类），`push_back` 可能会涉及额外的拷贝或移动操作，这可能会带来一些性能消耗。
   - `emplace_back` 是 `C++ 11` 引入的一个成员函数，用于在容器末尾直接构造一个元素；`emplace_back` 不需要先创建一个临时对象，而是直接在容器的内存空间中构造元素，这减少了不必要的拷贝和移动操作，提高了效率；函数原型：
   ```C++
   template <class... Args>
   void empalce_back(Args&&... args);
   // Args&&... args 是一个参数包，表示可以接受任意数量和类型的参数；这些参数会直接传递给元素类型的构造函数，用于在容器的末尾原地构造一个新元素
   ```
   - 如果需要添加一个已经存在的对象到容器中，可以使用 `push_back`
   - 如果需要将在容器中直接构造一个新对象，建议使用 `emplace_back`
   ```C++
   ...
   vector<string> vec;
   // 调用 push_back 时发生的事情：
   vec.push_back("hello");
   /* 1. 临时对象构造："hello" 被转换为一个 std::string 类型的临时对象。该过程会调用
    *    调用 std::string 的构造函数，将字符串字面量 "hello" 转换为一个 std::string 对*    象
    * 2. push_back 会将这个临时对象添加到 vec 中。根据 C++ 语义，push_back 的参数是一个*    右值引用（或左值）（const T& 或 T&&），它会根据传入的参数类型决定是（调用）复制*    还是移动（构造函数）。由于在上述例子中，临时对象是一个右值，因此 push_back 会调*    用 std::string 的移动构造函数，将临时变量的内容移动到 vec 的内部存储中
    * 3. 因此，上述语句中 push_back 会涉及两次构造函数调用
    */
    // 调用 empalce_back 时发生的事情：
   vec.emplace_back("hello");
   /* 1. 原地构造：emplace_back 的参数直接传递给容器中对象的构造函数。在这个例子中
    *    emplace_back 会将 "hello" 直接传递给 std::string 的构造函数，并在 vec 的
    *    内部存储中原地构造一个 std::string 对象
    * 2. 这个过程只涉及一次构造函数调用，即直接从 "hello" 构造为 std::string，从而避
    *    免了临时对象的创建和移动
    */
   ```

   2. `inset` 和 `push_back`
      对于以下代码：
      ```C++
      vector<int> test1;
      test1.push_back(1);              // 允许
      /* 对一个空的 std::vector 调用 push_back 方法时
       * push_back 会自动初始化向量并添加元素
       */

      vector<int> test2;
      test2.insert(test.begin(), 1);   // 不允许，未定义行为
      /* insert 方法需要一个迭代器作为插入位置的参数 
       * 如果向量是空的，那么 begin() 和 end() 方法返回的迭代器是未定义的
       * 因此不能直接使用它们作为插入位置
       */
      ```
      可以改写如下：
      ```C++
      /* 1. 先初始化向量 */
      std::vector<int> test;
      test.push_back(0);
      test.insert(test.begin(), 1);

      /* 2. 使用 reserve 方法预留空间，但不初始化元素 */
      std::vector<int> test;
      test.reserve(1);         // 预留空间，但不初始化元素
      test.insert(test.begin(), 1);

      /* 3. 为避免未定义的行为，可以在使用 insert 方法之前检查向量是否为空 */
      std::vector<int> myVector;
      if(myVector.empty()){
         myVector.push_back(1);
      }else{
         myVector.insert(myVector.begin(), 1);
      }
      ```

### `list`

1. 与 `vector` 的第 2 点进行对比，如下代码：
   ```C++
   std::list<int> myList;
   auto it = myList.begin();     
   // 允许，返回指向“尾后”位置的迭代器
   ```
   `std::list` 是一个双向链表，**它总是有一个有效的迭代器，即使列表为空**。因此 `std::list` 的 `begin()` 方法在空列表中是有效的。
   - `std::vector` 是一个*连续内存*的数组，其迭代器是基于指针的。**在空向量中**，`begin()` 和 `end()` 返回的迭代器是相同的，但是它们的**值是未定义的**。
   - 造成两者上述差异的原因：链表 `std::list` 的迭代器是双向指针，即使列表为空，`begin()` 也总是返回一个有效的迭代器，指向尾后位置；而向量 `std::vector` 的迭代器是基于指针的，空向量的 `begin()` 和 `end()` 返回的迭代器是相同的，但它们的值是未定义的。
   - 详情：1. **为什么 `std::list` 总是返回一个有效的迭代器**：`std::list` 是一个双向链表，它的每个节点都包含指向前一个节点和后一个节点的指针。即使列表为空，`std::list` 也会维护一个“尾后”迭代器（`end()`），这个迭代器指向链表的“尾后”位置。因此，begin() 和 end() 在空列表中总是返回有效的迭代器。`begin()`：返回指向链表第一个元素的迭代器。如果链表为空，返回的迭代器等于 `end()`，`end()`：返回指向链表“尾后”位置的迭代器。即使链表为空，这个迭代器也是有效的。2. **为什么 `std::vector` 在空容器中返回的迭代器是未定义的**：`std::vector` 是一个连续内存块的数组，它的迭代器是基于指针的。在空向量中，`begin()` 和 `end()` 返回的迭代器是相同的，但它们的值是未定义的。这是因为 `std::vector` 的迭代器实际上是内存地址的指针，空向量没有分配内存，因此 `begin()` 和 `end()` 返回的指针值是未定义的。`begin()`：返回指向向量第一个元素的迭代器。如果向量为空，返回的迭代器等于 `end()`，但其值是未定义的，`end()`：返回指向向量“尾后”位置的迭代器。如果向量为空，返回的迭代器值也是未定义的。
   - **迭代器和指针的区别**：
     1. 抽象性：
        1. 迭代器：是 `C++ `标准库中的一种抽象概念，用于提供对容器中元素的访问和遍历。迭代器的行为类似于指针，但它们可以有不同的实现方式，例如随机访问迭代器（如 `std::vector` 的迭代器）、双向迭代器（如 `std::list 的迭代器`）和输入/输出迭代器。
        2. 指针：是 C++ 中的一种原生类型，用于存储内存地址。指针可以直接进行算术运算（如加法、减法）和解引用操作。
     2. 实现方式：
        1. 迭代器：可以有不同的实现方式，例如基于指针的迭代器（如 `std::vector` 的迭代器）或基于对象的迭代器（如 `std::list` 的迭代器）。迭代器的实现方式取决于容器的类型和设计。
        2. 指针：总是基于内存地址的，直接操作内存地址。
     3. 安全性：
        1. 迭代器：通常比指针更安全，因为它们可以提供更多的检查和保护机制。例如，标准库容器的迭代器可以检测是否越界或是否指向已删除的元素。
        2. 指针：直接操作内存地址，容易导致错误，如野指针、内存泄漏等。
     4. 性能：
        1. 迭代器：性能取决于容器的实现。例如，`std::vector` 的迭代器基于指针，性能与指针相当；而 `std::list` 的迭代器基于对象，性能可能稍差。
        2. 指针：通常具有较高的性能，因为它们直接操作内存地址，没有额外的抽象层。
